### 2. claude-mem — Persistent context injection across every Claude session (78K stars)
**Source:** github.com/thedotmack/claude-mem · **Score:** 8/10
Single-command install (`npx claude-mem install`), six lifecycle hooks (SessionStart through SessionEnd), observations stored in SQLite, Chroma vector DB for hybrid semantic + keyword search. HTTP worker runs on port 37777 with a web viewer and 10 search endpoints. 3-layer query pattern: `search` (compact index) → `timeline` (chronological) → `get_observations` (full detail) minimizes token overhead. Works across Claude Code, Gemini CLI, OpenCode, OpenClaw. 78.3K stars / 6.7K forks.
**Why it matters:** 78K stars is the community saying this is the default persistent memory solution for Claude Code. For Leo's novel-writing pipeline: character state, plot decisions, and tone patterns persist automatically across sessions. The Chroma vector search means future sessions can query "what did I decide about Fate-Anchor's magic system?" and get an actual answer. More complex than claude-memory-compiler (requires Node.js 18+ + Bun + Chroma) but the scale of community validation is real.
**Build verdict: BUILDABLE — third-party code, safety gate applies; see briefing. Main tradeoff vs #1: more powerful search, higher system requirements.**
🔗 https://github.com/thedotmack/claude-mem
