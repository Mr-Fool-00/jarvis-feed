### 2. CC v2.1.200: Manual Mode Default + AskUserQuestion Breaking Change · Claude Code · 7/10

**Source:** GitHub Releases / X/@ClaudeCodeLog (July 3–4, 2026)

**What changed.** v2.1.200 shipped two changes that are breaking for automated/CI workflows:

**Breaking change 1: Permission mode renamed to "Manual."**  
The previous default permission mode was called "default." It's now called "Manual." Any scripts, config files, or runbooks that set `permissionMode: "default"` will need to update to `permissionMode: "manual"`. The behavior is the same; only the string value changed. But automated config parsing that checks for "default" will silently fall through to an unexpected state.

**Breaking change 2: AskUserQuestion no longer auto-continues.**  
Previously, if a CC session had a pending AskUserQuestion call and no human responded within the timeout, it would auto-continue with a null/default answer. As of v2.1.200, it **blocks indefinitely** unless you configure an idle timeout via `/config idleTimeoutMs=<ms>`. This is a significant change for any automated CC sessions (including CCR) that contain AskUserQuestion tool invocations — they'll now hang instead of proceeding.

**Non-breaking fixes in v2.1.200.**  
Background daemon improvements: stale lock file cleanup on startup, improved socket authentication, daemon handover on model switch, and data format forward-compatibility for daemon state files. These fix a class of "daemon won't start" errors that were appearing in Week 27.

**Subagent rate-limit behavior fix.** When a subagent hits its rate limit and terminates early, it now surfaces an explicit error notice ("subagent terminated due to rate limit") rather than returning an empty result silently. This is the fix that addresses the "my subagent returned nothing and I don't know why" debugging pattern.

**Impact on your stack.**
- CCR does not currently use AskUserQuestion, so the auto-continue change doesn't block this run. But if you ever add AskUserQuestion to Jarvis skills, add a `/config idleTimeoutMs=30000` step before any automated run.
- The permissionMode rename: check any CLAUDE.md files or settings.json files that hardcode `"default"` for the mode field.

### 3. Simon Willison: "Understand to Participate" · Essay · 7/10

**Source:** simonwillison.net, July 2, 2026 — covering Geoffrey Litt's AIE talk "Understanding Is the New Bottleneck"

**The core argument.** Geoffrey Litt gave a talk at the AI Engineering conference arguing that as LLMs become more capable, the bottleneck in human-AI collaboration has shifted from *generation quality* to *human comprehension of what was generated.* Willison covers this and extends it.

**The analogy.** Litt coins the term **cognitive debt** — a parallel to technical debt. Unreviewed AI code (or AI-generated writing) accumulates like technical debt: it works today but creates compounding opacity costs as the codebase (or manuscript) grows. You can merge fast now and pay the comprehension cost later, but "later" compounds.

**The 4 techniques Litt documented.** For keeping humans in the loop when AI output moves faster than human comprehension:

1. **Code explainer docs** — agents that generate not just code but a human-readable narrative of what the code does and why. The narrative is the comprehension artifact, not the code itself.

2. **Comprehension quizzes** — before merging AI output, a second agent constructs a quiz about the output. The human must pass the quiz to demonstrate they understand what they're accepting. Sounds patronizing; works empirically.

3. **Micro worlds** — for complex systems, build a simplified testable version alongside the real thing. The micro world is the comprehension scaffold — you can understand the micro world, and the micro world's behavior constrains the real system's behavior.

4. **Literate diffs** — diffs annotated with natural language explaining each change, written by the generating agent at generation time. Not postmortem explanation — the explanation is generated in the same pass as the change.

**Why this maps to your fiction pipeline.** The cognitive debt framing is directly applicable:
- Each scene an agent generates that you don't fully read is cognitive debt against the manuscript.
- The "comprehension quiz" pattern: after each chapter, a separate agent generates 5 questions about what just happened in that chapter. You answer them. Misses = places where the narrative isn't tracking for a reader (including the author as first-reader).
- Literate diffs: when a revision agent rewrites a scene, have it generate a narrative diff — "in the previous version X happened, in this version Y happened instead, because Z." Store alongside the file.

**Score rationale.** 7/10 — strong conceptual value for your pipeline; the cognitive debt framing is a good mental model; but no new buildable technique, and the core pattern (human comprehension of AI output) has been covered in prior runs (Osmani's evidence gate, July 4 PM run, is a concrete implementation of the same idea).
