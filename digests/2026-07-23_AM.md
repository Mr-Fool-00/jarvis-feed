### 4. SkillOpt (arXiv 2605.23904, Microsoft Research) — Skills as Trainable External State, +20pt Gains
**Source:** arxiv.org · **Score:** 8/10
Microsoft Research paper proposing that skill documentation should be treated as "trainable external state" rather than frozen prompts. The loop: agent executes a skill → outcome is evaluated → skill doc updates based on what worked vs. what didn't. Claimed +20 point gain on multimodal tasks (0.73 → 0.93 accuracy). Skills trained this way transfer across Claude Code and Codex without retraining. Published May 2026, still surfacing fresh because few practitioners have actually implemented it.
**Why it matters:** Jarvis's skills are static — once written, they don't improve from what happens in execution. SkillOpt proves closing that feedback loop works and isn't complex to build: you need an eval harness + a skill-updater agent. Run your chapter-generation skill through 10 books with this loop active and you'd have a materially better pipeline by book 11. Briefing in #improvements.
🔗 https://arxiv.org/pdf/2605.23904

Build verdict: BUILDABLE — concrete technique; the resulting component is an "eval + update" wrapper for any existing Jarvis skill; briefing posted to #improvements
