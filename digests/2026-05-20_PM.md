### 1. The Advisor Tool — pair Sonnet/Haiku executor with Opus advisor mid-generation
**Source:** Anthropic (platform.claude.com/docs) · **Score:** 9/10

Anthropic's Advisor Tool (beta since ~March 2026, now fully documented) lets a fast executor model (Sonnet 4.6 or Haiku 4.5) call Opus 4.7 mid-task for a strategic plan — without a second API request, context sync, or orchestration layer. The full conversation goes to Opus; Opus returns 400–700 tokens of guidance; the executor continues. All inside one `/v1/messages` call.

Benchmarks: Sonnet + Opus advisor = 74.8% SWE-bench Multilingual vs 72.1% Sonnet alone, at 11.9% LESS cost than pure Opus. Haiku + Opus advisor: 41.2% on BrowseComp vs 19.7% Haiku alone (2x+ jump).

Beta header: `anthropic-beta: advisor-tool-2026-03-01`.

**Why it matters:** This is your Council pattern as a native API primitive. Right now Jarvis's Council skill orchestrates separate Claude calls manually — expensive and complex. The Advisor Tool collapses that into one call: Haiku (or Sonnet) runs cheap bulk chapter generation, Opus drops in mid-task to course-correct craft decisions, voice drift, or plot logic. You get near-Opus quality on your writing pipeline at Sonnet cost. This directly cuts Leo's chapter-generation budget while improving output consistency. Build this into the writing skill first.
🔗 https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool

### 2. Claude Code CI Auto-fix + Remote Control — ship from anywhere, PRs fix themselves
**Source:** Anthropic (Code w/ Claude 2026) · **Score:** 8/10

Two features shipped at Code w/ Claude (confirmed for the London May 19 event, now in Max/Pro):

**CI Auto-fix** (`/autofix-pr`): Watches your PRs in the cloud. When CI fails, Claude reads the error, investigates, writes a fix, and pushes it to the branch with an explanation. When a reviewer comments clearly, Claude makes the change and replies to the thread — under your name, labeled "Claude Code." No manual re-run loop.

**Remote Control**: Sessions aren't tied to one machine. Dispatch a task from your phone, open the Desktop session it creates. Pull remote sessions into your terminal with `claude --teleport`. Step away mid-task, keep going on your phone.

**Why it matters:** Leo's book pipeline already generates PRs per chapter for review. CI auto-fix closes the loop — instead of waking up to "CI red, go fix it" you wake up to "CI green, PR merged." The teleport feature matters for late-night writing sessions where Leo wants to kick off a run on his Mac and check progress from his phone. Both features are available on Max plan now.
🔗 https://www.mindstudio.ai/blog/code-with-claude-2026-new-agent-features

### 3. Claude Code v2.1.145 — `claude agents --json`, OTEL spans, plugin preview
**Source:** Claude Code changelog (code.claude.com/docs) · **Score:** 8/10

Today's release (May 19-20, 2026) ships three genuinely useful changes:

1. **`claude agents --json`** — lists all live Claude sessions as structured JSON for scripting. Feed it into tmux-resurrect, status bars, or custom session pickers. Finally scriptable session management.
2. **`agent_id` + `parent_agent_id` in OTEL spans** — trace parenting now correctly nests background subagent spans under their dispatching Agent tool span. This makes multi-agent trace graphs in Honeycomb/Datadog actually readable.
3. **`/plugin Discover`** — shows a plugin's full manifest (commands, agents, skills, hooks, MCP servers) before you install. No more guessing what a plugin touches.

**Why it matters:** `claude agents --json` is the piece Leo's been missing for the Jarvis multi-session dashboard. You can now write a shell script that lists all running sessions, their durations, and their parent relationships — making the Agent View pattern (from a previous digest) scriptable without the GUI. The OTEL span fix means Leo's book pipeline trace graphs will finally show agent hierarchy correctly when multiple chapter agents run in parallel.
🔗 https://claudelog.com/claude-code-changelog/
