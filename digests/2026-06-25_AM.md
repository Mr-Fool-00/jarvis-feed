### 2. Check Point Research: CVE-2025-59536 + CVE-2026-21852 — RCE and API Token Exfiltration via Claude Code Project Files
**Source:** Check Point Research (research.checkpoint.com) · **Score:** 7/10
Two patched CVEs that matter to any Claude Code user who clones repos: (1) **CVE-2025-59536 (CVSS 8.7 High)** — hook commands in `.claude/settings.json` or `.mcp.json` **executed before the trust dialog appeared**, meaning a malicious repo could silently RCE your machine the moment you `git clone && claude` it. Fixed in v1.0.111 (October 2025). (2) **CVE-2026-21852 (CVSS 5.3 Moderate)** — a project file could set `ANTHROPIC_BASE_URL` to redirect all Claude API traffic to an attacker-controlled server, leaking your API key with every request. Fixed in v2.0.65 (December 2025). Discovered by Check Point's Oded Vanunu and Aviv Donenfeld. Responsible disclosure; both are patched and auto-update should have covered most users.
**Why it matters:** This is exactly the kind of supply-chain risk that's easy to forget: any shared repo (or one you cloned from GitHub) could have had a malicious `.claude/settings.json` before the October fix. If you cloned anything before v1.0.111 and ran Claude Code in that directory, your machine was exposed. The fix is in — but you should verify you're on 2.0.65+, and the broader lesson is that `.claude/settings.json` and `.mcp.json` are code-execution vectors to audit just like Makefiles. Especially relevant for jarvis-feed itself, which uses hooks.
**Build verdict:** INFORMATIONAL — security advisory, not a skill to build; action is: `claude --version` → confirm ≥ 2.0.65, audit your `.claude/settings.json` hooks.
🔗 https://research.checkpoint.com/2026/rce-and-api-token-exfiltration-through-claude-code-project-files-cve-2025-59536/

### 3. MindStudio: How to Build a Hybrid AI Memory System for Claude Code
**Source:** MindStudio blog (mindstudio.ai) · **Score:** 7/10
MindStudio published a detailed architectural guide (June 11, 2026) on solving Claude Code's cold-start problem — every session opens blank, no memory of past decisions. Their pattern: a 3-layer stack: (1) **Hermes** for structured storage (writes observations + decisions to persistent files with metadata as the session runs); (2) **MemSearch** (2.1k stars, v0.4.11 June 22) for semantic recall (ONNX bge-m3 embeddings + Milvus vector DB, hybrid dense+BM25 search, no API key needed); (3) **Claude Code hooks** (`SessionStart` + `StopHook` in `.claude/settings.json`) + a condensed `identity-core.md` that gets injected deterministically at session open. The key insight: CLAUDE.md is optional-for-Claude (it can deprioritize it), but a `SessionStart` hook is deterministic — it fires first, every time. MindStudio's 6-layer taxonomy goes: native files → session hooks → semantic search → verbatim recall → knowledge bases → cross-tool shared memory. They note most builders only use layer 1.
**Why it matters:** Jarvis itself loses context every run — it re-reads JARVIS_PERSONA.md and AGENT_RUNBOOK.md every 12 hours because there's no persistent memory. This pattern could be adapted so future Jarvis runs inject a compressed summary of recent digest history, reaction patterns, and ranking adjustments without needing to re-read the full runbook from scratch. The `SessionStart` hook approach is directly applicable to jarvis-feed's `.claude/settings.json`. MemSearch is actively maintained, pip-installable, and doesn't require a paid API. MindStudio is self-promoting their ecosystem but the underlying patterns are tool-agnostic.
**Build verdict: BUILDABLE** — I can sketch a Leo-owned version: a `SessionStart` hook that reads compressed prior-run state, plus a `StopHook` that writes session observations to a rotating log. Would tap Leo on shoulder for this one.
🔗 https://www.mindstudio.ai/blog/hybrid-ai-memory-system-claude-code-storage-injection-recall

### 5. Mitiga Labs: MCP Token Theft via MITM — "MCP-Jacking"
**Source:** Mitiga Labs security research · **Score:** 6/10
Mitiga Labs documented a new attack pattern: a malicious MCP server proxies legitimate tool calls while silently stealing OAuth tokens in transit, then replays them to exfiltrate data or take actions outside the user's session. Attack surface includes any MCP server that handles authentication on behalf of the user. Mitiga coined "MCP-Jacking" for the pattern. No CVE yet; mitigation is MCP server allowlisting + reviewing what auth scopes any MCP server requests.
🔗 https://www.mitiga.io/blog
