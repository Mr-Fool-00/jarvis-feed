### 1. CC v2.1.198 — Background Agents Auto-Commit, Push, and Open Draft PRs; Two New Notification Hooks
**Source:** aiagentsfirst.com, github.com/anthropics/claude-code/issues/73197 · **Score:** 7/10
**URL:** https://aiagentsfirst.com/claude-code-v2-1-198-background-agents

Released **July 1, 2026**, v2.1.198 closed the last gap in the background agent workflow. Previously, agents would finish in a worktree and stop — requiring a human to commit and push. Now agents in `claude agents` worktree mode:

1. **Commit all changes** when the task completes
2. **Push the branch** automatically
3. **Open a GitHub draft PR** (marked draft, not ready-for-review)

The draft PR boundary is deliberate: CI runs, the diff is reviewable, but no reviewer notification fires and the merge button is inactive until a human flips it to ready. The agent does the work and stages the result; the merge decision remains human.

**Scope boundaries:**
- Applies **only** to worktree-isolated agents (`claude agents` sessions) — never to non-worktree checkouts
- Agents **never** push to main/master, never force-push, never merge
- Non-worktree checkout modes still follow normal permission prompts

**Two new Notification hook events added in the same release:**
- `agent_needs_input` — fires when a background agent is blocked waiting for user input
- `agent_completed` — fires when a background agent finishes its task

Both events are surfaced through the existing `Notification` hook mechanism. Wire them to a Slack webhook or desktop alert in `settings.json` → `hooks.Notification`.

**The catch — no off-switch:** GitHub Issue #73197 (`anthropics/claude-code`) is an open feature request for `backgroundAgents.autoCreatePr: false` and separate `settings.json` knobs for auto-commit / auto-push / auto-PR. Not yet implemented as of v2.1.207. If you run background agents on a private project, PRs are being opened without an explicit opt-in per-run.

**Relevance to Jarvis:** The `agent_completed` notification hook is directly applicable — wire it to the Slack webhook for session-end alerts instead of relying on commit-prefix routing. Could replace the current notify: pattern for Jarvis's own heartbeats.

**Build verdict:** INFORMATIONAL — wire `agent_completed` hook to SLACK_WEBHOOK_GENERAL if you want Jarvis to self-notify on task completion without needing a commit.

### 2. oh-my-openagent (omo/lazycodex) — 65.7K Stars, Agent Harness for "Tokenmaxxers"
**Source:** github.com/code-yeongyu/oh-my-openagent · **Score:** 6/10
**URL:** https://github.com/code-yeongyu/oh-my-openagent

`oh-my-openagent` is an agent orchestration harness layered on top of AI coding agents — primarily targeting **OpenCode** (Ultimate Edition, 11 agents) and **Codex CLI** (Light Edition, portable components). Claude Code is a secondary supported target via shared components.

**What makes it interesting:**

- **Hash-anchored edits:** Every line gets a content hash tag before agent edits. The harness validates that the hash matches before applying the edit, preventing stale-line errors — described in the project docs as "the most common agent failure mode isn't the model, it's the edit tool." This is an architectural pattern, not a CC-specific trick.

- **11 specialized agents with automatic routing:** Sisyphus (orchestrator), Hephaestus (deep worker), Prometheus (planner), Oracle (architecture review), Librarian (docs/search), Explore (codebase grep) + 5 more. Tasks are routed to the right agent automatically based on work category.

- **5 built-in MCPs:** Exa (web search), Context7 (official documentation lookup), Grep.app (GitHub code search), LSP (code intelligence), AST-Grep (structural pattern search).

- **Tokenmaxxing philosophy:** Maximum useful output per API dollar through intelligent routing, parallel agent execution (Team Mode), and efficient context management. The goal is not to burn fewer tokens — it's to get more done per dollar spent.

- **54+ lifecycle hooks:** Full hook system across the agent execution lifecycle; each hook is opt-out via `disabled_hooks` in config.

**Why it's relevant if CC-secondary:** The hash-anchored edit pattern, routing-by-work-category architecture, and tokenmaxxing discipline are all concepts applicable to any multi-agent pipeline including CC-based orchestration. The project's approach to "agent failure modes" (edit staleness, context waste) is worth studying.

**Build verdict:** NOT BUILD_WORTHY — primarily an OpenCode harness, not a CC skill or MCP. The hash-anchored edit pattern is worth noting for future CC hook development.
