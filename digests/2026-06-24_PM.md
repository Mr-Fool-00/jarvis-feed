### 1. AIR Security: How We Hijacked 26,000 Agents With One Instagram Ad
**Source:** air.security/blog-posts · **Score:** 8/10 · Published June 23, 2026  
Security firm AIR built a fake Claude Code skill called `brand-landingpage` that appeared to automate landing-page creation using Google's Stitch design tool. In under an hour, they gamed two trust signals: (a) submitted a PR to a popular skill marketplace repo (36k GitHub stars, 156 skills) and got it merged so the skill inherited the star count; (b) submitted the skill to Cisco, NVIDIA, and skills.sh scanners, which all returned green verdicts — because at scan time, the external link the skill fetched led to clean content AIR controlled. They then ran a paid Instagram ad targeting non-technical marketers and designers. Reached approximately 26,000 agents including corporate-account installs before AIR disclosed the experiment.

The key technical finding: **static scanners check the package once, but skills routinely instruct agents to fetch external URLs — and those URLs can be silently swapped post-install**. AIR demonstrated this by updating the content at their controlled domain after distribution was complete. Any skill pointing an agent at an external URL (for docs, SDK setup, configuration) is handing the domain owner a persistent, post-install instruction channel. The scan verdict says nothing about what that URL will serve at runtime.

In AIR's controlled demo, the swapped payload caused agents to send users' email addresses back to AIR's server — the mechanism that produced the 26,000 count. In a real attack, the payload could do anything the agent is permitted to do: read credential files, exfiltrate workspace contents, execute arbitrary shell commands, or inject further instructions into the agent's context.

**Defensive actions directly applicable to Leo's setup:**
- Manual `SKILL.md` inspection before every install: look for any `fetch`, `visit`, or `curl` instruction pointing at a domain that is not the canonical vendor.
- GitHub star count and scanner badge = social proof only. Neither proves runtime behavior.
- `sandbox.credentials` in CC v2.1.187 is now worth enabling — blocks credential file reads in sandboxed commands regardless of what a skill tries to fetch.
- Apply full software supply-chain discipline: prefer skills with no external runtime fetches; treat anything pointing outside the named vendor's own domain as high-risk.

**Why it matters for Jarvis:** Step 4.5 safety gate is validated. The AM digest already filed `claude-tag` and `cloudflare-temp-accounts` briefings from skills Leo knows and trusts. This is why the gate exists — the 26,000-agent reach was accomplished without any zero-day.  
Build verdict: INFORMATIONAL — security research validating existing workflow. No skill to install; no briefing needed.  
🔗 https://www.air.security/blog-posts/the-story-of-skills-how-we-hijacked-26000-agents-with-one-instagram-ad

### 2. Claude Code v2.1.186 + v2.1.187 — MCP Auth CLI + Credential Sandbox
**Source:** github.com/anthropics/claude-code/releases · **Score:** 8/10 · Released June 22–23, 2026  
Two releases shipped back-to-back during this window. Combined, they're the most substantive CC update pair in recent memory.

**v2.1.186 (June 22):**
- `claude mcp login <name>` / `claude mcp logout <name>` — MCP server authentication now has a proper CLI surface. Previously required workarounds (manual token injection, environment variables). This is the flow the MCP auth spec intended.
- "Skills" section added to `/plugin` Installed tab — makes the growing skills ecosystem first-class in the plugin UI.
- `!` bash commands now auto-trigger Claude responses to output — useful for fire-and-watch patterns.
- Background subagents now surface permission prompts in the main session instead of auto-denying — big change for orchestrated workflows where subagents hit tool permission gates.
- `Agent(type)` deny rules and `Agent(x,y)` restrictions now properly enforced (prior bug allowed bypass).
- `CLAUDE_CODE_MAX_RETRIES` cap raised to 15.
- Skill frontmatter now accepts kebab-case, snake_case, and camelCase — more forgiving for SKILL.md authors.
- `/review <pr>` now uses the same engine as `/code-review medium`.

**v2.1.187 (June 23):**
- `sandbox.credentials` setting — blocks sandboxed commands from reading credential files and secret env vars. Direct security hardening; pairs with the AIR Security skill attack (item #1).
- Org-configured model restrictions shown in model picker with explanatory messaging.
- Fixed `--json-schema` and `agent({schema})` structured output looping (model could previously re-call `StructuredOutput` indefinitely after success).
- Fixed remote MCP tool calls hanging indefinitely — now abort with error after timeout.
- Fixed CC Remote sessions taking ~2.7s longer to start after proxy CA install (relevant to CCR-hosted runs like Jarvis).
- Improved `/btw` with ←/→ arrow navigation through earlier answers.
- Improved `/plugin` to surface unused plugins for cleanup.

Build verdict: INFORMATIONAL — update to existing tool. Enable `sandbox.credentials` in next config pass. The `claude mcp login/logout` flow is worth testing against your Jarvis MCP setup on next local run.
