### 1. Addy Osmani: "Agentic Code Review" — 33,707 PRs, Comprehension Debt, and the Evidence Gate · Blog · 7/10

**Source:** addyosmani.com/blog/agentic-code-review/ (July 3, 2026)

**What happened.** Google Chrome VP of Engineering Addy Osmani published a deep analysis of agentic code review at scale, drawing from a dataset of 33,707 agent-generated PRs. The central finding: AI agents ship code faster than humans can understand it. He names this **comprehension debt** — teams merge agent PRs they cannot actually read — and frames it as the structural risk of autonomous development, not hallucinations or bugs per se.

**The five patterns he documented:**

1. **Evidence gate** — require agents to output their own reasoning before merge: "what did I change, why, what did I verify." Not a description but a machine-readable evidence artifact reviewers can inspect. PRs that included this evidence had 40% lower post-merge regression rates in his dataset.

2. **Fresh-window self-review** — agents that perform a self-review pass *in a new context window* (no memory of the generation session) catch bugs and contradictions that same-session review misses. The fresh-window reviewer is functionally blind to "what the code was supposed to do" and evaluates only what it does.

3. **Autonomy level logging** — each PR tagged L0–L4 (L0=human-written, L4=fully autonomous, no human review). Allows postmortem analysis by autonomy level. "We found L3–L4 PRs had 2.7x the revert rate of L0–L1. We didn't know that until we had the labels."

4. **Circuit breaker** — if an agent-generated area of the codebase generates >N bug reports in M days, flag it as high-maintenance and require human review for the next K PRs touching that area. Explicit cooldown mechanism for runaway agent contribution.

5. **28% merge instantly** — 28% of agent PRs in his dataset merged with zero human review, zero comments. That cohort had the highest post-merge defect rate. The evidence gate targets exactly this cohort.

**Why this matters for your fiction pipeline.** Replace "PR" with "chapter" and "codebase" with "novel draft" and every one of these patterns maps:
- Evidence gate → require your chapter-writer agent to output "what happened in this scene, what continuity promises I'm making, what I verified against the world state" before the scene is accepted.
- Fresh-window self-review → a second agent instance with no memory of the drafting session reads the output and flags inconsistencies. This is cheaper than a full Auditor agent and works per-scene.
- Circuit breaker → if a particular character's scenes keep generating continuity flags, quarantine that character's arc for human review.
- Autonomy logging → tag chapters by autonomy level for postmortem (fully generated vs. outline-guided vs. human-started).

**Action:** No install required. Adapt the evidence gate pattern to your next Jarvis fiction pipeline session: before accepting a scene, prompt the writer agent to produce a 150-word evidence artifact (what happened, what was verified, what continuity claims are made). Store that artifact alongside the scene file.

### 2. CJS Framework: Cyber Jailbreak Severity — CVSS for AI Jailbreaks · Industry · 7/10

**Source:** Anthropic Security Blog · Amazon + Microsoft + Google co-signatories (July 2026)

**What it is.** The Cyber Jailbreak Severity (CJS) Framework is a four-axis scoring system for AI jailbreak vulnerabilities, jointly developed by Anthropic, Amazon, Microsoft, and Google. It is explicitly modeled on CVSS (the industry-standard vulnerability scoring system for traditional software) and is designed to give security teams a common language for triaging AI safety incidents.

**The four axes:**

| Axis | What it measures |
|------|-----------------|
| **Capability Gain** | How much the jailbreak expands the model's effective capability beyond its policy boundary |
| **Universality (Breadth)** | Does it work on one model only, or across multiple models/providers? |
| **Ease of Weaponization** | How much skill/effort does exploitation require? |
| **Discoverability** | How easy is it for attackers to find or derive independently? |

**Severity bands:** CJS-0 (Informational) → CJS-1 (Low) → CJS-2 (Moderate) → CJS-3 (High) → CJS-4 (Critical). Bands are exponential — a CJS-4 jailbreak is not "a little worse than CJS-3" but an order of magnitude broader in potential impact.

**The Mythos connection.** The CJS Framework is what powers Anthropic's "Mythos" cybersecurity classifier, which shipped as part of Fable 5's safety stack. Mythos scores jailbreak attempts in real-time using CJS axes and gates Fable on CJS-3/4 patterns. This is why Fable came back from the US export control suspension with a more robust cybersecurity story — the classifier is the condition that was satisfied to get clearance.

**Why it matters to you.** Direct impact: if you're running Jarvis subagents that do prompt-level iteration (experimental prompts, test-harness jailbreak-detection), this is the vocabulary your tests should be thinking in. More broadly: CJS is going to become the standard taxonomy for AI security reporting the way CVSS became the standard for CVE reporting. Security blogs, model provider changelogs, and enterprise risk assessments will start citing CJS scores. Worth knowing the schema now.

**No action required** — informational, industry-standard framework. Read the Anthropic Security Blog post if you want the full scoring rubric.
