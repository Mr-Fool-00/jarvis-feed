### 2. MCP Final Spec RC — Stateless Core, 9 Days to Publish (July 28)
**Source:** blog.modelcontextprotocol.io · **Score:** 8/10
The MCP 2026-07-28 Release Candidate locks in a stateless architecture: the `initialize` handshake is gone, `Mcp-Session-Id` is eliminated, and SSE server-push streams are replaced with request/response pairs. Protocol version and client capabilities now travel in `_meta` on every individual request rather than being established once. Net result: MCP servers can run behind round-robin load balancers with no sticky routing. What breaks for existing servers: anything that stores state in session IDs needs to migrate to "explicit handles" (model-carried identifiers minted from tool calls). Error code `-32002` → `-32602`. The Tasks API is fully redesigned around stateless lifecycle. Roots, Sampling, and Logging are deprecated with a 12-month window. Extensions get formal reverse-DNS namespacing.
**Why it matters:** Every MCP server you or your team connects to Claude Code will need to update before or shortly after July 28. The GitHub MCP server, the PulseMCP MCPs, the Gmail MCP — they all run under this spec. If any of them break in your Claude Code setup after July 28, this is why. More importantly: the stateless model enables horizontal scaling of MCP servers, which is what Anthropic's Managed Agents architecture requires. The brain/hands decoupling post (item #6) is the product-level consequence of this protocol decision.
🔗 https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/

**Build verdict: INFORMATIONAL — protocol infrastructure; Leo doesn't run MCP servers, but his toolchain does.**

The Compaction as Epistemic Failure paper from the July 18 digest is directly relevant: CC was optimized for the 73% HIL case, not the 0.8% long-autonomous case you're in.
