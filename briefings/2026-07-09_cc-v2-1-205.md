# Briefing: CC v2.1.205 — Auto-Mode rm -rf Guard, /doctor Command, Colored Agent States, Transcript Protection

**Score:** 8/10 · **build_worthy:** ✅ YES
**Source:** Claude Code changelog · July 8, 2026, 21:22 UTC

---

## Why this matters

v2.1.205 is the most consequential CC changelog in months. Three of the changes directly affect how Leo runs multi-agent pipelines: the rm -rf guard changes the safety profile of auto-mode, /doctor gives you a diagnostic tool you've never had before, and colored agent states make stuck agents visible without having to parse terminal noise.

---

## Change-by-change breakdown

### Auto-mode rm -rf guard (critical for pipelines)

CC now intercepts destructive file operations (`rm -rf`, recursive deletes, file overwrites of non-temp paths) in auto-mode and requires explicit confirmation before proceeding — even if the agent called the tool.

**What this changes for pipelines**: any pipeline step that deletes scratch files, cleans build directories, or wipes temp state automatically will now pause and wait for confirmation. If your pipeline runs fully headless, this could cause hangs at cleanup steps.

**Action**: test your existing pipelines on v2.1.205. If you have cleanup steps that ran silently before, you may need to either:
- Add explicit `--allow-destructive` flags to the relevant tool calls
- Restructure cleanup to use `rm` on specific named files rather than `rm -rf` on directories

The guard is the right call for safety. It just requires verifying your existing automation doesn't assume silent deletes.

### /doctor command

New built-in diagnostic. Run it in any CC session:
```
/doctor
```

Checks and reports on:
- Shell config validity (PATH, env vars CC depends on)
- Tool availability (git, gh, node, python, etc.)
- MCP server connectivity (each configured server gets a health check)
- CC config validity (syntax errors, unknown keys in settings.json)
- Memory and disk health

This has been missing for years. Previously debugging "CC is behaving strangely" meant grep-ing through settings files manually. Now: `/doctor` first.

### Colored agent states

The terminal state display now color-codes each agent:
- 🟢 Green: running (active tool call or model inference)
- 🟡 Yellow: waiting (on user confirmation, on a sub-agent, on an MCP server)
- 🔴 Red: error (tool call failed, model returned error)
- ⚫ Grey: idle (completed, waiting for next task)

During multi-agent runs, this replaces the previous "wall of text" progress output with a scannable state grid. Stuck agents (yellow for >30s without state change) are now immediately visible.

### Streaming auto-updates

CC's self-update (`/update`) previously loaded the entire update package into memory before writing it. Now it streams. Peak memory during update dropped ~400MB. Matters in containers and constrained CI environments where CC was previously OOM-killing itself during update.

### Transcript protection

CC now refuses to delete session transcript files (`.claude/transcripts/`) even when a tool call or agent requests it. Previously possible to accidentally wipe a transcript via a cleanup script that globbed `.claude/*`. Now protected.

### Bug fixes

- **Windows NTFS path normalization**: backslash/forward-slash handling in tool paths fixed on Windows
- **Background agent crash on large outputs**: agents producing >50MB of output no longer crash the background runner
- **Session-to-PR linking**: `gh pr` integration now correctly links the session to the PR instead of the branch
- **MCP server connection hang**: servers with slow initialization (<10s) no longer cause CC to hang on session start
