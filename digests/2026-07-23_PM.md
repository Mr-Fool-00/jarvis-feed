### 1. Claude Security Plugin — Official Anthropic Beta, Multi-Agent Vulnerability Scanner in Your Terminal (July 22)
**Source:** claude.com/blog/claude-security-public-beta · x.com/claudeai · marktechpost.com · **Score:** 9/10

Anthropic shipped Claude Security as an official Claude Code plugin in public beta. It's not a linter — it's a coordinated multi-agent pipeline: one agent maps architecture and builds a threat model, specialist agents hunt for vulnerabilities across files and data flows, and an independent agent reviews every finding before writing the report. Scan your full codebase or just a commit/PR diff, right from the terminal. Patch suggestions are generated and reviewed by a second independent agent that also runs the project's test suite against the change before handing the patch to you.

Covers 25+ vulnerability types: injection flaws, auth bypasses, memory corruption, logic errors, race conditions. Requires CC v2.1.154+, paid plan, Python 3.9.6+, Dynamic Workflows enabled. Enabled at claude.ai/admin-settings/claude-code. Full docs at code.claude.com/docs/en/claude-security.

**Why it matters:** This is a native Anthropic security review agent with independent-agent verification built in — the same adversarial-verify pattern that makes multi-agent systems more reliable. The independent reviewer design is directly applicable to the Leo pipeline: instead of one agent validating its own output, spin a separate agent to refute it. The commit-diff scan mode is exactly what you'd want pre-push on jarvis-feed. This is the most significant official CC plugin release since Skills.

🔗 https://claude.com/blog/claude-security-public-beta

Build verdict: BUILDABLE — enable on jarvis-feed immediately; run `/security` on the next commit batch. The independent-reviewer pattern is worth extracting as an architectural principle for Jarvis multi-agent flows.

### 2. Claude Managed Agents — July 22 Release Notes: Effort Settings, Expanded Webhooks, Session Seeding
**Source:** platform.claude.com/docs/en/release-notes · **Score:** 7/10

Four updates in Tuesday's Managed Agents release:
- **Effort settings** on agent model configuration: pass `effort: "standard" | "high" | "xhigh" | "max"` inside the model object at agent creation. Claude allocates compute internally — no token-juggling required.
- **Expanded webhook coverage**: four environment event types + three memory_store event types. You can now react to environment and memory store lifecycle events without polling.
- **Session seeding**: pass initial events when creating a session to pre-warm agent context.
- **Event deltas for thread streams**: thread stream events now include only the diff rather than the full state.

🔗 https://platform.claude.com/docs/en/release-notes

Build verdict: INFORMATIONAL — the `effort:` parameter is immediately useful if you're building managed agents for the Leo pipeline; no new skill needed, just parameter awareness

### 4. Sophos: AI Coding Agents Triggering Endpoint Security Rules Built for Human Attackers (July 8)
**Source:** sophos.com/en-us/blog/2607_agents_vs_telemetry · thehackernews.com · **Score:** 5/10

Seven days of Sophos endpoint telemetry from June 2026 showed Claude Code, Cursor, and OpenAI Codex setting off detection rules written to catch human intruders. The agents aren't malicious — they just do things that look exactly like attacks to a behavioral engine: decrypting browser credentials, pulling files with `certutil.exe -urlcache -split -f`, writing to the startup folder, cycling through LOLBins when one gets blocked. The persistence pattern (try → blocked → retry with different LOLBin) mirrors hands-on-keyboard attacker behavior.

Sophos's recommendation: scope existing rules by agent parent process (claude.exe, cursor.exe, child processes) and workspace path rather than creating agent-specific exceptions wholesale.

🔗 https://thehackernews.com/2026/07/ai-coding-agents-found-triggering.html

Build verdict: INFORMATIONAL — good ops hygiene reading if you or your clients run CC in enterprise environments with endpoint detection; no skill output

### 5. Fabula — Google DeepMind Narrative Storytelling Sidekick Co-Designed with 42 Writers (arXiv:2606.14411)
**Source:** arxiv.org/abs/2606.14411 · research.google · **Score:** 5/10

Research prototype from Google DeepMind (built on Gemini) that structures fiction hierarchically: story → scenes → beats, each independently generatable and revisable. Co-designed with 42 expert screenwriters and playwrights through participatory design interviews and writing sessions. Key design choices interrogated: (1) whether an auto-evaluator optimized on expert preferences improves story quality, (2) whether exposing the full narrative plan in the UI helps or hurts, (3) whether narratological assumptions generalize across traditions, (4) whether convergent iteration over a story plan supports creativity.

Not CC-native, not Claude-based. The hierarchical beat/scene structure and participatory evaluation methodology are the transferable ideas.

🔗 https://arxiv.org/abs/2606.14411

Build verdict: INFORMATIONAL — architectural reference for Leo's chapter pipeline; the beat/scene hierarchy maps to chapter substructure; Gemini-based so not directly adoptable
