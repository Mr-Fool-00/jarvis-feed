**Source:** simonwillison.net · July 8, 2026
**URL:** https://simonwillison.net/2026/Jul/8/rewriting-bun-in-rust/

The best production-scale multi-agent case study since the Devin paper. Simon ran 64 parallel Claude instances over 11 days ($165K total) to port the Bun JavaScript runtime to Rust — and it passed all existing Bun test suites on day 11. Key architectural patterns:

- **Dynamic workflow sizing**: agent fleet scales up/down from a single config value based on task parallelism — no manual fleet resizing
- **Adversarial-per-struct review**: every Rust struct definition goes through an independent Claude instance that tries to break it before it gets committed — catches subtle invariant violations a single agent misses
- **Parallelism boundary heuristic**: agents were assigned at the file/module level, not line level — coarser than you'd expect, but avoids merge conflicts and context bleed

Why this matters now: these patterns are directly stealable. The adversarial-per-struct loop is 30 lines of agent orchestration. The dynamic fleet sizing is a `FLEET_SIZE` constant in `/config`. Briefing has full breakdown.

### 8 · 📄 7/10 · build_worthy ❌ — arXiv 2607.07321: "Atomic Actions → Standard Operating Procedures" — LLM Agents Self-Evolve by Synthesizing Reusable Multi-Step Tool Sequences
**Source:** arXiv (cs.AI) · July 8, 2026
**URL:** https://arxiv.org/abs/2607.07321

Authors propose that LLM agents can self-evolve by recognizing recurring sequences of atomic tool calls and synthesizing them into named **Standard Operating Procedures (SOPs)** — callable higher-order tools that encapsulate the multi-step logic. Over time, the agent's toolset grows from built-in atomics to domain-specific SOPs it built itself, reducing per-task reasoning overhead.

Concrete example from the paper: an agent that repeatedly does `read_file → parse_json → validate_schema → write_output` synthesizes a `process_config_file(path)` SOP. Next time it needs the same sequence, one call replaces four, and the reasoning step disappears.

**The connection to CC skills**: this is the formal grounding for what CC skills do manually. The SOP synthesis pattern could be implemented in Jarvis: after a run, have Claude identify recurring tool-call sequences in the session transcript and propose them as new skill candidates.
