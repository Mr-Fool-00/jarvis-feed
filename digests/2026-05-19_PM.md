**Why it matters:** Dreaming is the thing your writing pipeline has been missing at the system level — a way for Claude to accumulate craft knowledge across chapter sessions without you manually writing it into prompts. The Outcomes loop is your current "judge-reviewer" pattern made native and automatable. Multiagent at 25 concurrent threads is the infrastructure for the Council skill to run at production scale. ### 2. Claude Code Agent Teams — Official Multi-Agent Orchestration (Experimental)
**Source:** claude.com docs (code.claude.com/docs/en/agent-teams) · **Score:** 9/10

Claude Code v2.1.32+ ships with native Agent Teams — disabled by default, enabled via `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` in settings.json. The architecture:

- **Team lead**: your main Claude Code session. Creates the team, spawns teammates, coordinates via a shared task list.
- **Teammates**: separate Claude Code instances with their own full context windows. They communicate directly with each other via a mailbox system (not through you, not through the lead). They self-claim tasks from the shared list. You can Shift+Down to cycle through them and message any teammate directly.
- **Hooks**: `TeammateIdle`, `TaskCreated`, `TaskCompleted` — you can enforce quality gates (exit code 2 = block + send feedback) at every handoff.
- **Plan approval mode**: spawn a teammate in read-only plan mode; lead reviews and approves/rejects before implementation starts.
- **Subagent reuse**: define a role once (security-reviewer, chapter-fixer, voice-checker) and use it both as a subagent and as a teammate.

Key constraint: no nested teams (teammates can't spawn their own teams), one team at a time, no session resumption for in-process teammates. Token cost scales linearly with teammates — 3-5 teammates is the practical sweet spot.

**Why it matters:** This is the Claude Code implementation of what you've been building manually in Jarvis's Council skill — except it's native, it handles task coordination, inter-agent messaging, and quality gates without you writing the orchestration glue. Your Council currently has Claude simulate multiple advisors in one context; Agent Teams gives each advisor its own context window with real parallelism. For your writing pipeline specifically: imagine a chapter-drafter teammate, a voice-consistency-checker teammate, and a continuity-judge teammate all working the same chapter simultaneously, challenging each other's outputs. Enable it now and test on a non-critical chapter.

🔗 https://code.claude.com/docs/en/agent-teams

### 3. HadiFrt20/deepresearch — Autonomous Multi-Session Research Agent for Claude Code
**Source:** github.com/HadiFrt20/deepresearch · **Score:** 9/10

A Claude Code skill that turns your session into a full autonomous research pipeline. Install to `~/.claude/skills/deepresearch`, then:

- `/dr-new`: interactive setup (11 questions) that generates a full project scaffold — execution protocol, 80–120 atomic tasks, schemas, evaluation criteria, and project-local subagents. This is your research plan.
- `/dr-run`: executes the task tree autonomously, spawning isolated subagents for each task, verifying every output against schemas, and running each factual claim through a dedicated **adversary agent** that actively tries to disprove it. Claims that survive get a trust score; claims that fail are flagged for human review.
- Leave it running overnight, come back to structured findings.

The adversary-agent-per-claim design is the key differentiator — it prevents the usual problem where Claude confirms its own assumptions. Every claim has provenance and an adversarial pass before it reaches you.

**Why it matters:** Your Kindle writing pipeline currently has no real research phase — you write the world bible manually or skip sourcing entirely. This changes that. For a novel chapter that needs accurate historical details, technical mechanisms, or character motivation consistency, you'd run `/dr-new` with the research question, `/dr-run` overnight, and wake up to verified source material with trust scores. The same infrastructure applies to worldbuilding deep-dives for Fate-Anchor or Shadow Emperor — run a deep research pass on a mythology system, come back to structured lore with sourced references. This is directly installable today, no API key required, runs on your Max plan.

🔗 https://github.com/HadiFrt20/deepresearch
