## 🏆 Top picks

### 1. SkillRevise: Execution-Grounded Skill Revision · score 7/10
**Source:** arxiv:2606.01139 · June 2, 2026  
**What:** "Execute → diagnose → revise → re-execute" loop for improving LLM agent skills from execution evidence. Framework automatically identifies failing skill components from runtime traces and applies targeted rewrites. Tested across GPT-5.5, Qwen-3.6+, DeepSeek-V4-Pro. Consistent gains with zero human labeling.  
**Why it matters to you:** This is literally your skill debugging workflow, formalized. Next time a Claude Code skill fails, don't rewrite from scratch — feed the execution trace back in and ask Claude to diagnose the failing component specifically. The paper's diagnosis→patch loop is something you could wire into your skill update routine.  
**Link:** https://arxiv.org/abs/2606.01139

### 2. SkillAdaptor: Step-Level Skill Failure Attribution · score 7/10
**Source:** arxiv:2606.01311 · June 1, 2026  
**What:** Training-free framework that identifies the *first failing step* in a multi-step skill trajectory, attributes it to a specific skill clause, and applies a targeted fix rather than rewriting the whole skill. Key finding: "stable agent improvement depends less on expanding skill libraries, more on accurately attributing failures to specific steps."  
**Why it matters to you:** This reframes how to think about your growing skill library — the bottleneck isn't adding more skills, it's fixing the specific step where existing ones break. Complements SkillRevise above; together they suggest a diagnostic-first approach over iterative rewrites.  
**Link:** https://arxiv.org/abs/2606.01311

## 📈 Trends spotted

**Skill self-improvement cluster** — four independent papers published June 1-9 (SkillAdaptor, SkillRevise, Declarative Skills, MUSE-Autoskill) are all converging on the same architecture: execute → identify the first failing step → targeted revision rather than full rewrite. This is not coincidental timing; it's a research cluster responding to the same observed problem with production skill libraries. The emerging standard: every skill has an attached execution trace, and the improvement loop runs diagnostics before rewrites.

If this cluster lands (and the empirical results across all four papers are consistent), the "pile more skills in" approach hits a wall and diagnostic-first becomes the default. Worth tracking whether CC's skill system ships something in this direction by Q3.
