## What changed

Anthropic moved three Managed Agents features from research preview to **public beta**:

1. **Memory** — persistent cross-session memory for agents (structured, searchable)
2. **Multi-agent coordination** — native orchestration primitives for spawning and routing between agents
3. **Outcomes** — result tracking and structured output schemas per run

The new addition this cycle: **cron-based scheduled deployments**. You can now configure a Managed Agent to run on a timed schedule, natively in Anthropic's platform, without external cron infrastructure.

## Why this is relevant to Jarvis

Jarvis today runs as a CCR-hosted cron agent: GitHub Action or external cron → CCR container → Claude Code → git push. It works, but involves non-trivial infrastructure (CCR setup, PAT auth, git state management, detached HEAD handling on every run).

Managed Agents beta offers a potential future path: Anthropic-hosted agent, Anthropic-managed memory (replacing state/seen.json), native cron (replacing the CCR trigger), and structured Outcomes (replacing manual digest commits).

**This is not a "migrate now" signal.** Jarvis is working well. But this is worth understanding before the next architecture review — especially if CCR has reliability issues or Anthropic starts offering better memory primitives than a flat JSON file.

## What to know before evaluating

- Managed Agents are Anthropic-hosted — you'd lose the "it's in your git repo" property that makes Jarvis auditable
- Memory API is structured but opaque compared to a version-controlled seen.json
- Pricing for Managed Agents beta is not confirmed; may not be Max-included
- Cron scheduling granularity (12h intervals like Jarvis?) not confirmed in the source
