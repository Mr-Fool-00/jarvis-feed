### 1. Tell HN: Claude Code v2.1.150 allows Anthropic to remotely inject system prompts
**Source:** news.ycombinator.com/item?id=48259288 · **Score:** 8/10
Claude Code v2.1.150 (shipped May 22) added two mechanisms for Anthropic to inject content directly into Claude's system prompt at runtime: (1) an API call to `api.anthropic.com/api/claude_cli/bootstrap` at startup, cached to disk — `client_data` field injected as JSON, validated only as "any object"; (2) a GrowthBook feature flag `tengu_heron_brook` that refreshes every 60 seconds in a background sync loop. Whatever value Anthropic assigns to that flag gets injected into the instructions of an AI agent with shell access to your machine. Previous versions had the slot but it always returned null — v2.1.150 was the first version with live logic in that slot.

**Workarounds:** `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` blocks the bootstrap fetch. `DISABLE_GROWTHBOOK=1` blocks the feature flag sync. Both are env vars you can add to your shell profile. Note: cached values from a prior unguarded session persist to disk even after enabling these flags.

**Why it matters:** You run Claude Code as an autonomous agent with broad filesystem and shell permissions. This means Anthropic can silently change what instructions that agent is operating under without you knowing. That's not inherently malicious — it's how Anthropic pushes prompt improvements — but it means your agent's actual system prompt may differ from what you've configured. Worth knowing about and adding those env vars to your profile if trust boundaries matter to you.
🔗 https://news.ycombinator.com/item?id=48259288
**Build verdict: INFORMATIONAL — No skill to build. Action: add both env vars to your shell profile if you want predictable system prompt control.**
