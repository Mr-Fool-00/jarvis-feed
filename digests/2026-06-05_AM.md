### 1. "Comment and Control" — Prompt Injection via GitHub Comments Hits Claude Code, Gemini CLI, and GitHub Copilot
**Source:** SecurityWeek / Aonan Guan (Johns Hopkins) · **Score:** 7/10

Security engineer Aonan Guan published a full disclosure June 4 of a prompt injection technique dubbed "Comment and Control" that compromises all three major AI coding agents simultaneously: Claude Code Security Review, Google's Gemini CLI Action, and GitHub Copilot Agent. The attack vector is GitHub PR titles, issue bodies, and comments — content the agents auto-read when GitHub Actions triggers fire on `pull_request`, `issues`, and `issue_comment` events. Unlike traditional indirect prompt injection that requires a victim to trigger something, this is **proactive**: simply opening a PR or filing an issue can activate the agent with no victim interaction required.

For Claude Code specifically: the Claude Code Security Review action interpolates the PR title directly into Claude's prompt **with zero sanitization**. An attacker opens a PR whose title breaks out of the prompt context and instructs Claude to run `env` or `ps auxeww` — returning a full credential dump from the CI environment. The `GITHUB_TOKEN`, AWS creds, or any other secrets in the Actions environment are exposed to the attacker.

For Gemini CLI: by injecting a fake "Trusted Content Section," the attacker overrides safety instructions, causing Gemini to post the `GEMINI_API_KEY` as a **public issue comment**. For Copilot: three Microsoft runtime mitigations (env var filtering, secret scanning, network firewall) were all bypassed. The core issue affects all three because they all share the same fundamental trust model: the AI reads external content and acts on it.

**Why it matters:** Leo's current setup doesn't run Claude Code in GitHub Actions CI, so this isn't an immediate threat. But: (a) if you ever add claude-code-security-review or claude-code-action to any public repo's workflow, any anonymous person on the internet can steal your CI secrets with a single PR title; (b) the attack class (AI agent reads external content → executes it) is the same fundamental problem that the skills security wave surfaced for SKILL.md files last week — this is the GitHub variant; (c) if you're building out the Jarvis GitHub integration further (e.g. a PR-monitoring or auto-label agent), you need to design for this from day one.

**Build verdict:** INFORMATIONAL — security advisory. No skill to build. Practical action if ever using claude-code-security-review: PR title sanitization + strip all injection patterns from trigger inputs before they reach Claude.

### 2. Claude Code GitHub Actions Flaw — Single Issue Could Hijack Any Repo Running claude-code-action (Fixed in v1.0.94)
**Source:** The Hacker News / GMO Flatt Security (RyotaK) — disclosed June 4, 2026 · **Score:** 7/10

Separate from the "Comment and Control" story above, security researcher RyotaK of GMO Flatt Security published a full technical disclosure of a vulnerability in the **claude-code-action** GitHub Action itself (Anthropic's official action that lets Claude automatically review and fix issues in your CI pipeline). The bug was a broken permission check: the `checkWritePermissions` function unconditionally trusted any GitHub actor whose username ended in `[bot]` — regardless of whether that bot actually had write access to the repository.

**Attack chain:** GitHub Apps have implicit read access to public repos and can create issues via an installation token. An attacker creates a GitHub App, gets an installation token, files an issue on any public repo using claude-code-action, and fills the issue body with a prompt injection payload that looks like an error message. Claude "recovers" from the fake error by running the commands embedded in it. The real prize: the OIDC credential pair that CI uses to request a signed token, which Claude Code then trades with Anthropic's backend for a **write-access GitHub App installation token**. With that, the attacker can push malicious code to the repo — and since Anthropic's own action repo used the same workflow, a successful attack could have poisoned the action itself and every downstream project that pulls from it (supply chain attack).

CVSS v4.0 score: **7.8**. RyotaK reported to Anthropic in January 2026; Anthropic fixed it within four days. The disclosure was withheld until June 4 to allow full spring hardening. The fix is in **claude-code-action v1.0.94**.

**Why it matters:** Same caveat as item #1 — Leo doesn't currently run claude-code-action in GitHub Actions CI. But (a) this confirms the attack model works end-to-end against AI coding agents in CI, (b) the supply-chain angle is genuinely scary — if Anthropic's own action repo could be hijacked to push malicious code into the action itself, that's a different level of risk than a credential dump, (c) if Leo ever adds any Anthropic-maintained GitHub Action to his pipeline, he should verify it's on v1.0.94+ and keep an eye on the releases.

**Build verdict:** INFORMATIONAL — patched, awareness only. Check the version of any claude-code-action in any public repo you contribute to: should be ≥ v1.0.94.

### 3. CC v2.1.163 — `/plugin list` Command + Managed Settings Version Gating
**Source:** Official Claude Code changelog (June 4, 2026) · **Score:** 6/10

Claude Code v2.1.163 shipped June 4. Key changes:

1. **`/plugin list --enabled` / `--disabled`** — New command to inspect what plugins/skills are currently loaded and their state. Previously you had to know what you'd installed; now you can audit your active skill/plugin set from the CLI.
2. **`requiredMinimumVersion` / `requiredMaximumVersion` managed settings** — For enterprise teams managing a fleet of Claude Code installs via managed settings, you can now enforce a version floor/ceiling. Prevents a stale install from running workflows that require newer primitives.
3. **`$` escape syntax for skills** — Skills can now include literal `$2`-style strings by escaping the `$`. Previously any `$` followed by a digit was interpreted as a template variable, which could break skill files referencing regex patterns or dollar amounts in prose.
4. **Background session task fix** — Sessions were losing their assigned tasks on update; fixed.
5. **Keyboard input fix** — Keyboard input was becoming unresponsive after paste operations in some terminals; fixed.

**Why it matters:** The `/plugin list` command is directly useful — when you're managing a fiction pipeline with multiple loaded skills (writer, editor, continuity, worldbuilding), a fast CLI audit of what's active is useful before kicking off a long session. The `$` escape fix matters if any of your skill files contain dollar-amount references or regex patterns that were getting mangled.

**Build verdict:** INFORMATIONAL — `npm install -g @anthropic-ai/claude-code` to upgrade.

🔗 https://code.claude.com/docs/en/changelog
