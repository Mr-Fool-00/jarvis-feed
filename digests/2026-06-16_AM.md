### 3. Nested sub-agents 5 levels deep — Claude Code v2.1.172 (June 10)
**Source:** note.com/meichanai, ofox.ai/blog, claudefa.st · **Score:** 8/10

Shipped quietly in v2.1.172 (released June 10 at CwC Tokyo): sub-agents can now spawn their own sub-agents, up to 5 levels of nesting. Each level carries its own system prompt and model assignment. The parent only reads the leaf node's summary output — intermediate layers cost tokens but aren't exposed to the root.

Architecture notes: This is recursion with a 5-frame stack limit. Nesting is cheap to set up, expensive in tokens if overused. Each level's full context window runs independently. The intermediate layers' work vanishes from the root's view — only the final summary propagates up.

**Why it matters:** This enables patterns your current Council skill can't do. Right now: one Opus orchestrator calls several Sonnet workers (1 level). With 5 levels: Opus orchestrator → Sonnet department heads → Haiku specialists → Haiku validators → Haiku leaf workers. For your book pipeline specifically: Chapter planner (Level 1) → Scene orchestrator (Level 2) → Scene writer + internal critic (Levels 3-4) → Line-level polish agent (Level 5). All in one `claude agents` invocation. The "sub-agent end-of-run review" pattern (where a sub-agent reviews its own output before returning to parent) is now native at every level. Caveat: intermediate token cost is real — don't nest more than needed.
