### 3. Claude Code Silently Deletes Your Transcripts — Anthropic Closed the Issue "Not Planned" · HN · 8/10

**Sources:** HN:48732846 · GitHub [#59248](https://github.com/anthropics/claude-code/issues/59248) · [#62476](https://github.com/anthropics/claude-code/issues/62476) · [#62959](https://github.com/anthropics/claude-code/issues/62959) · [The Register](https://www.theregister.com/ai-and-ml/2026/06/30/claude-code-users-complain-their-chat-records-are-being-mysteriously-wiped-out/5264673)

**What happens.** Claude Code runs a background cleanup ~12 minutes after every session start. Default: `cleanupPeriodDays: 30`. Mechanism: `unlink()` — hard deletion, bypasses macOS Trash. Files deleted: all `.jsonl` session transcripts in `~/.claude/projects/`. Orphaned subagent directories (10–15 MB each) are left behind as dead weight. Ghost sidebar entries remain pointing to non-existent sessions, erroring with "session not found on disk" when clicked.

**Anthropic's response.** Issue #62959 closed as **"not planned"** with labels `data-loss`, `bug`, `stale`. Official justification: transcripts can contain credentials, keeping them indefinitely creates security risk. The community notes this reasoning would support a soft-delete or opt-in model rather than silent hard-deletion.

**Critical gotcha.** `"cleanupPeriodDays": 0` does **NOT** disable cleanup — it disables all transcript writing entirely (documented in issue #23710). The correct disable-cleanup value is `36500` (100 years).

**Fix right now:**
```json
// ~/.claude/settings.json
{
  "cleanupPeriodDays": 36500
}
```

**Why this hits your fiction pipeline hard.** Every planning session, character development discussion, plot branch exploration, and subagent task history is a `.jsonl` file. Your Jarvis orchestration sessions alone generate dozens of these. At 30 days, months of creative reasoning context is silently destroyed. Additionally: if mtime on a transcript is touched by a sync client (Dropbox, rsync, Cursor's file watcher), deletion may trigger earlier than expected. Bug #62272 documents premature deletion triggered by CC updates and restarts.

**Action:** Add the setting above. Consider a daily `rsync ~/.claude/projects/ <backup_dir>` to a separate directory as belt-and-suspenders, since issue #62272 shows even high retention values can be bypassed by update cycles.
