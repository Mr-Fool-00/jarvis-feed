## v2.1.218 (July 29)

### `context: fork`

**What it does:** When invoking a tool or skill with `context: fork`, the current full conversation context (not a summary — the full context) is copied into the spawned subagent. The subagent starts with everything the parent agent knows.

**What it changes:** Previously, spawning a subagent required explicitly passing context — either summarizing the relevant state, or writing it to a file the subagent could read. Summarization loses information. `context: fork` eliminates the summarization loss for subagent spawns.

**What to watch for:** A forked subagent starts with full context but operates independently — its edits don't propagate back to the parent. The pattern is "give subagent full awareness, collect its output" not "shared mutable state."

**Where to use it in the fiction pipeline:**
```
# Before (explicit context passing):
chapter_agent = spawn("draft chapter 7", context=chapter_brief)

# After (full context fork):
chapter_agent = spawn("draft chapter 7", context=fork)
# Agent has full knowledge of chapters 1-6, character sheets, style guide, everything
```

The continuity fixer and voice checker benefit most — they need full manuscript context to catch inconsistencies, and previously got summarized excerpts.

### `/code-review` as Background Subagent

`/code-review` now spawns a background agent and returns focus to the main loop immediately. Results arrive asynchronously. The main agent can continue other work while the review runs.

**Usage pattern:**
```
# In a hook or after a diff:
/code-review  # spawns background, returns immediately
# ... continue with other steps ...
# Review results arrive when ready
```

This also means `/code-review` can be chained after automated build steps without blocking the pipeline.

### `workflowSizeGuideline` Key in Settings

New settings key that configures the target agent count for workflow-style runs. Previously the default was hardcoded. Now you can override per-session or per-project:

```json
// .claude/settings.json
{
  "workflowSizeGuideline": "medium"  // or "small", "large", "unlimited"
}
```

Useful for Jarvis runs where you want to control subagent proliferation explicitly.

## v2.1.219 (July 30)

See the Opus 5 briefing (`briefings/2026-08-03_opus5-launch.md`) for routing and cost implications.

### `DirectoryAdded` Hook

A new CC hook that fires whenever a new directory is created during a session. Hook receives the created directory path.

**Use case — chapter scaffolding automation:**
```json
// .claude/settings.json
{
  "hooks": {
    "DirectoryAdded": [
      {
        "matcher": "chapters/*",
        "command": "scripts/scaffold-chapter.sh"
      }
    ]
  }
}
```

When CC creates `chapters/ch07/`, the hook fires and runs the scaffolding script (e.g., copy chapter template, initialize continuity log, create draft placeholder). This is the hook the fiction pipeline has been missing for automated chapter setup.

### Nested Subagent Depth 3

Previously, agents could spawn agents (depth 2). Now agents can spawn agents that spawn agents (depth 3). The concurrency cap (default 20) is enforced across all levels.

**Practical implication for fiction pipeline:** The orchestrator can now run:
- Orchestrator (depth 0)
  - Chapter drafter (depth 1)
    - Reference checker (depth 2) — verifies chapter against canon database
      - [Previously: depth 3 was blocked. Now: can spawn specialized sub-checkers]

This is mostly future-proofing — the fiction pipeline doesn't currently use depth > 2 — but the constraint no longer applies when designing new multi-agent patterns.

Change the chapter drafter spawn to use `context: fork` so each chapter agent has full manuscript context, not a summarized brief. This is especially important for chapters 5+ where continuity dependencies are dense.

**Priority 2 — DirectoryAdded hook for chapter scaffolding:**

Add a `DirectoryAdded` hook matched to the `chapters/` pattern. When CC creates a chapter directory, auto-run: template copy, continuity log init, character reference symlink. Removes manual setup between chapter drafts.

**Priority 3 — /code-review in the pipeline:**

If any pipeline step generates code (CC skills, hook scripts), add `/code-review` as a background step. Non-blocking so it doesn't slow down the main pipeline.
