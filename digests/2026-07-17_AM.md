### 1. arxiv:2607.01418 — Microsoft CC/Copilot CLI Empirical Study `arxiv:2607.01418-microsoft-cc-study` · Score: 8/10

**Source:** arXiv (cs.SE) · Murphy-Hill, Butler, Savelieva (Microsoft Research)  
**Why it matters:** First peer-reviewed field study measuring the real-world output impact of agentic coding tools at enterprise scale. Tens of thousands of Microsoft engineers, four-month window, developer-level telemetry, PR merges as the productivity proxy. Key findings: (1) **+24% more PRs merged** by adopters vs. matched non-adopters, lift persisted across the full four months; (2) **first adoption spread through social networks**, not top-down IT rollouts — meaning organic peer-to-peer uptake is the dominant pattern; (3) **retention correlated with baseline coding activity**, not seniority or team; (4) startling finding: **Copilot CLI adopters showed a larger PR lift than CC adopters**, despite CC consistently winning on developer sentiment in public comparisons.

**Postscript that matters:** By June 2026, Microsoft began canceling Claude Code licenses and redirecting engineers to Copilot CLI. That decision was made AFTER the study window — but the PR data may have informed it. Worth reading if you care about the business case for CC in enterprise settings.

**Build_worthy:** No — field study, not a buildable pattern. But read the paper.

🔗 https://arxiv.org/abs/2607.01418

### 2. "Context Rot" — Governing Claude Code Session Decay `tds:context-rot-2026-07-13` · Score: 8/10

**Source:** Towards Data Science / daton.app (July 13, 2026)  
**Why it matters:** Coins a real term for a real problem: progressive degradation of Claude Code session quality as context fills. The article identifies three failure modes — **instruction drift** (earlier system prompts fade in attention), **fact contamination** (stale file contents shadow updated reads), and **attention dilution** (every new tool call competes with an ever-longer context). Governance patterns proposed: periodic context snapshots to `state/`, explicit context pruning hooks triggered at N-tool-calls, and session handoff protocols (compacting session state to a fresh agent).

**Leo relevance:** Fiction pipeline sessions running 3–6 hours are exactly the scenario described. A 75k-token session in chapter 12 of a novel draft is carrying plot state from chapter 1 that Claude may be misapplying. The pruning hook and session handoff patterns are directly implementable as CC hooks in settings.json.

**Build_worthy:** YES — the context-snapshot hook and pruning trigger are buildable now.

🔗 https://towardsdatascience.com/governed-context-managing-context-rot-in-claude-code/  
(mirror: https://www.daton.app/2026/07/context-rot-why-claude-code-sessions.html)

### 5. Claude Code 33k Token Front-Load vs. OpenCode 7k `hn:48883275-33k-tokens-opencode` · Score: 7/10

**Source:** HN:48883275 / Piebald-AI (July 13, 2026)  
CC sends ~33k tokens to the model before your first prompt (27 tool definitions = ~24k, system prompt = ~6.5k). OpenCode sends ~6.9k (10 tools). In a real dev environment with MCPs + CLAUDE.md, CC's pre-prompt overhead hits **75k tokens**. Important nuance: because CC batches more tool calls per turn, its whole-task total can end up lower than OpenCode's which re-pays its smaller baseline turn after turn.
