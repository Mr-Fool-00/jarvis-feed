### 3. "Loop Engineering" — Boris Cherny + Addy Osmani, June 2026
**Score: 7/10** | Source: The New Stack + addyosmani.com (June 2026) | Build verdict: BUILD_WORTHY ✅

Boris Cherny (head of Claude Code at Anthropic) and Addy Osmani (Google Chrome) independently published on the same concept in June:

> **"I no longer prompt. I write loops."** — Boris Cherny

The idea: instead of manually prompting an agent and evaluating the result, write a *loop* — a small tick-based program that:
1. Prompts the agent with a task
2. Reads the output
3. Decides: done? or loop again with a correction?
4. Re-prompts with adjusted context if needed

Osmani frames it as "agent harness engineering": the loop IS the product, not the prompts inside it.

**Why this is build-worthy for Leo:** Leo's fiction pipeline is already loop-shaped — generate chapter → evaluate → revise. But Jarvis itself is a loop that doesn't know it's a loop. A `/loop-engineer` skill could scaffold this pattern: define an exit condition, define a verifier agent, wire the tick-based re-prompt. Especially valuable for long-form scenes where "good enough" needs to be programmatically detectable, not human-reviewed each iteration.

**Signal source:** Boris Cherny quote sourced from The New Stack interview + Addy Osmani's addyosmani.com blog (confirmed via WebSearch June 2026). See full briefing: `briefings/2026-06-19_loop-engineering.md`
