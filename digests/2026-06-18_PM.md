## 🔥 Top 3

### 1. AdaptOrch — topology selection beats model selection in multi-agent systems (12-23% gains)
**Source:** arxiv 2602.16873 · **Score:** 6/10

AdaptOrch (preprint, circulating this week on HN / r/LocalLLaMA) proposes a meta-orchestrator that selects the optimal multi-agent topology per task rather than committing to a single static architecture. Key finding: choosing the right topology (chain, tree, star, mesh, debate) achieves 12-23% performance improvement over static single-topology baselines — even when using identical underlying models at each node. The system classifies tasks by cognitive demand, then routes to the matched topology. Debate topologies win on tasks requiring adversarial checking; chain wins on sequential reasoning; star (single orchestrator, parallel workers) wins on decomposable workloads.

**Why it matters:** This directly maps to Leo's Council skill and the fiction pipeline. The current Council implementation uses a fixed topology (parallel workers → synthesis). AdaptOrch's insight: if the task is "generate 3 competing chapter outlines," a debate topology would self-correct toward coherence better than parallel generation. If it's "write chapter 7 given chapter 6," a chain wins. The 12-23% gain is achievable without changing models at all — just by routing. This is the most actionable architecture finding in months.

🔗 https://arxiv.org/abs/2602.16873

**Build verdict:** INFORMATIONAL — no installable package. But the topology-routing logic is buildable as a Council skill enhancement: a pre-step that classifies task type → selects topology before dispatching workers.

### 3. Apple Foundation Models + Claude as swappable backend (WWDC June 9 — delayed capture)
**Source:** Apple WWDC 2026 / developer.apple.com · **Score:** 5/10

Captured this run (missed by 10-day gap). Apple Foundation Models (on-device) is the default; Claude 4 (via Anthropic API) is explicitly supported as a drop-in via the `AnthropicLanguageModelAdapter` package. **Why it matters:** This changes the iOS developer toolchain — Claude is now a first-class backend option in Apple's own IDE, not an external addition. If Leo's projects ever touch iOS/macOS development, this is the native integration path. ### 4. Agent-Reach — 34K-star unified social MCP (⚠️ Safety gate applied)
**Source:** GitHub / PulseMCP trending · **Score:** 5/10

Agent-Reach is a trending MCP server (34K stars, #1 on PulseMCP this week) that provides a single MCP interface for reading content from Twitter/X, Instagram, LinkedIn, XiaoHongShu (RED), YouTube, GitHub, and RSS — all through a unified `search_content`, `get_feed`, and `monitor_topic` tool set. Uses yt-dlp for YouTube, twitter-cli for Twitter/X, feedparser for RSS, and unofficial scraping for Instagram/LinkedIn/RED.

**Step 4.5 safety gate applied.** Red flags: (a) Instagram, LinkedIn, and XiaoHongShu access uses unofficial methods — session cookies, browser automation, or scraping — which is a ToS violation on all three platforms. (b) The twitter-cli dependency accesses the X platform without an official API key, which violates X's developer terms. (c) No documentation on where credentials are stored or whether they're transmitted. Decision: MIT license and open source don't override platform ToS risk. Informational note only — not recommending installation. **If Leo wants social monitoring integrated into Jarvis, the correct path is building a native reader using official APIs (YouTube Data API v3, Reddit API, GitHub API) — all of which are already used in Jarvis's SOURCES.yaml.**

🔗 https://github.com/agent-reach/agent-reach
