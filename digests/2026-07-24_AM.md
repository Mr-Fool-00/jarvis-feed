### 3. Beam.ai: 6 Multi-Agent Orchestration Patterns for Production
**Source:** beam.ai/agentic-insights/multi-agent-orchestration-patterns-production · **Score:** 8/10

A production-focused catalog of six orchestration patterns with cost tradeoffs included. The three most relevant to Leo's pipeline:

(1) **Council pattern** — run Claude Sonnet 4.6 and GPT-5.4 in parallel, use a judge model to arbitrate. Adds ~2.5× cost versus a single writer but measurably improves output reliability. The article names this as the architecture behind Microsoft Copilot Council.

(2) **Critic/Judge distinction** — critics emit suggestions without gate authority; judges emit binary go/no-go decisions. Mixing these roles in the same agent is the source of most quality-gate failure modes.

(3) **Fixer pipeline** — judge flags failures → fixer agent applies patches → output re-enters the pipeline. The article includes the termination signal pattern (APPROVED keyword) from the BrightCoding briefing Leo already has.

**Why it matters:** This is the clearest single-document reference for the architecture that underlies the Council skill and the planned `/book-pipeline` skill. The council pattern cost math ($2.5× for the arbitration layer) gives Leo a concrete budget number to validate the Opus 4.8 economics against his Max plan. The critic/judge role separation is the exact fix for the quality-gate inconsistency in the current pipeline.

🔗 https://beam.ai/agentic-insights/multi-agent-orchestration-patterns-production

Build verdict: BUILDABLE — this is the design spec for the `/book-pipeline` v2 that's been sitting in the build queue. React 🚀 to kick off the implementation briefing.

### 5. OrchRM: Reward Modeling for Multi-Agent Orchestration (arXiv:2606.13598, June 2026)
**Source:** arxiv.org · **Score:** 8/10
Self-supervised framework for training a judge model that evaluates orchestration quality without human annotations. Constructs win/lose pairs from intermediate artifacts (partial outputs, agent traces) to train a Bradley-Terry reward model. The resulting judge can score orchestration decisions — parallelism, delegation quality, aggregation — without labeled data. The self-supervised approach means a judgment model could be trained purely from Leo's existing overnight chapter runs.
🔗 https://arxiv.org/abs/2606.13598
