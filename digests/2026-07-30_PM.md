### 1. Claude Code Sends 33k Tokens Before Reading Your Prompt — Systima Study
**Source:** Systima AI / HN 48883275 (538 pts, 303 comments) · **Score:** 10/10

Systima instrumented the API layer between Claude Code v2.1.207 and OpenCode v1.17.18, both running against the same model on identical hardware. CC front-loads ~32,800 tokens per request: 6,500-token system prompt + ~24,000 tokens of tool schemas (27 tools described on every API call). With MCP servers active, that balloons to ~75,000 tokens — consuming 37.5% of the 200k context window before your prompt even begins. OpenCode equivalent: 6,900 tokens.

The more important finding is the companion "Subagent Tax" paper: fan-out orchestration (parallel subagents for council or review chains) costs **5.9x the tokens** of an equivalent serial run, with no actual wall-clock speedup. And — traced to v2.1.198 — the built-in Explore subagent now inherits the main session's Opus model instead of being pinned to Haiku. This is a **silent cost regression**: any fan-out pipeline running after July 1 without explicit model pinning now costs dramatically more. Pinning subagents back to Haiku saved 37% tokens and cut runtime to under half in Systima's tests.

**Why it matters:** For overnight fiction pipelines, this is cumulative. Every CC turn pays the 33k pre-prompt tax. Every subagent launch multiplies it by 5.9x. If your pipeline uses council/review chains, that multiplier is live on your account right now. On a 200k-context run with 4 parallel subagents, you're burning ~300k tokens in scaffolding before any creative work happens.

**Immediate actions:**
- Pin all subagents to Sonnet or Haiku explicitly — never let them inherit the parent session's Opus model
- Audit which MCP servers are loaded per pipeline — unload unused ones before overnight runs
- Check whether Explore subagent invocations in your pipeline are running Opus (regression since July 1, 2026)

**Build verdict:** INFORMATIONAL/ACTIONABLE — No skill to build, but 3 concrete config changes needed now. Full briefing in #improvements.

### 2. Claude Code: Anatomy of a Misfeature — AskUserQuestion Auto-Continue
**Source:** Olaf Alders / HN 48947776 (140 pts, 118 comments) · **Score:** 9/10

On July 1, 2026, Anthropic silently shipped CC v2.1.198 with a **60-second auto-continue timer on AskUserQuestion** — the blocking safety gate that pauses Claude and waits for human input when it hits ambiguity. If you didn't respond within 60 seconds, Claude silently proceeded using "best judgment." The feature was absent from the changelog, couldn't be disabled without finding a hidden env var (`CLAUDE_AFK_TIMEOUT_MS`) shared only peer-to-peer in a GitHub issue, and directly inverted the human-in-the-loop contract.

GitHub issue #73125 collected 384 upvotes and 143 comments. Thariq (Anthropic CC team) acknowledged the change on HN, apologized, and clarified: the timeout only starts if the terminal lacks focus and cancels on any keypress — details that were never documented. Anthropic reverted the behavior in v2.1.200 on July 3, three days after shipping it. The feature is now opt-in via `/config` as a configurable timeout window. The `CLAUDE_AFK_TIMEOUT_MS` env var still exists.

**Why it matters:** For overnight fiction pipelines, this misfeature was a direct threat — Claude would silently resolve ambiguous plot or character decisions at 2am with no audit trail. The revert is in place (current version v2.1.220), but the pattern matters: Anthropic shipped a safety-gate behavior change with no changelog, no docs, no opt-in. The config option is now live and could be accidentally enabled. Audit before your next overnight run.

**Immediate actions:**
- Run `claude /config` → verify no AFK timeout is set
- Search pipeline launch scripts for `CLAUDE_AFK_TIMEOUT_MS` (should be unset or 0)
- Add `CLAUDE_AFK_TIMEOUT_MS=0` explicitly to overnight pipeline invocations as a defensive measure

**Build verdict:** INFORMATIONAL/ACTIONABLE — Config audit required now. Full briefing in #improvements.
