### 2. CoEvoSkills: Self-Evolving Agent Skills via Co-Evolutionary Verification
**Source:** arXiv:2604.01687 · **Score:** 7/10
April 2, 2026. CoEvoSkills enables LLM agents to autonomously generate and iteratively refine multi-file skill packages without ground-truth signals. The key mechanism is "information-isolated surrogate verification" — structured failure diagnostics that close a skill evolution loop. 71.1% pass rate on SkillsBench (vs 30.6% no-skill baseline, +40.5pp). Evaluated across 87 tasks in ~20 professional domains. Teams from University of Illinois Chicago, Columbia, Chonnam National University, and UBC.

**Why it matters:** The self-improvement loop pattern here — run skill → observe failure via surrogate → extract diagnostic → update skill — is the same pattern your Jarvis nightly cron could formalize. The "co-evolutionary" piece means the verification criteria co-evolve alongside the skill, preventing skills from overfitting to stale tests. Directly relevant to the Jarvis self-improvement cycle you're building toward.

**Build verdict: INFORMATIONAL** — Academic paper, no open-source codebase yet. Core pattern (skill generation → surrogate verification → diagnostic feedback → skill refinement) is a reference architecture for how to structure Jarvis's improvement loop.

🔗 https://arxiv.org/abs/2604.01687

### 3. EvoAgent: Evolvable Agent Framework with Skill Learning and Multi-Agent Delegation
**Source:** arXiv:2604.20133 · **Score:** 7/10
April 22, 2026. EvoAgent models skills as multi-file capability units with triggering mechanisms and "evolutionary metadata" — continuous skill generation and optimization via user-feedback-driven closed-loop. Three-stage skill matching strategy (semantic → capability → context fit) plus three-layer memory for long-term capability accumulation. 28% average score improvement under 5-dimensional LLM-as-Judge evaluation in real-world foreign trade scenarios.

**Why it matters:** The "evolutionary metadata" concept — tracking which skills need refinement based on task outcomes, and using that signal to continuously improve the skill library — is directly applicable to how your book pipeline skills could improve over time. **Build verdict: INFORMATIONAL** — Research paper without a matching open codebase yet. The 3-stage matching pattern and evolutionary metadata structure are worth studying when you build out the Jarvis skill management layer.
