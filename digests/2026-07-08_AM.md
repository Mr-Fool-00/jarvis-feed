### 5. Addy Osmani: "The Code Agent Orchestra" — Conductor vs. Performer Model · 7/10 ⭐ BUILD WORTHY
**Source:** Addy Osmani (Google Chrome engineering lead) · **Date:** July 2026
Framework for multi-agent orchestration: a single **conductor** agent handles task decomposition, context threading, scope negotiation, and escalation decisions. **Performer** agents execute in parallel, each with bounded scope and no global context. Conductor holds the thread; performers are stateless within a task. Key insight: the coordination problem in agent teams isn't "use more agents" — it's structuring *authority and information flow* so the conductor never becomes a bottleneck and performers never step on each other.
**Why it matters:** Leo's Jarvis v2 planning involves moving from the current single-agent digest pipeline to a multi-agent architecture. The conductor/performer model is a directly applicable blueprint — Jarvis could have a conductor that routes to specialized performers: fetch-agent, rank-agent, brief-agent, delivery-agent.
