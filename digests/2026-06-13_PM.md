### 2. Agentjacking: fake Sentry error events hijack Claude Code with 85% success rate
**Source:** tenetsecurity.ai · **Score:** 8/10

Tenet Security published research on a new attack class they call "Agentjacking." The attack exploits the intersection of how Sentry receives error events (via a public DSN — write-only, discoverable from browser JS or GitHub) and how MCP-connected coding agents process them. The attacker posts a fake error event containing malicious instructions to a target organization's Sentry DSN. When Claude Code, Cursor, or Codex retrieves the error via the Sentry MCP, the agent reads the crafted payload as a legitimate bug report and executes the attacker's commands with the developer's own system privileges.

Controlled test results: 85% hijack success rate against all three agents tested (Claude Code, Cursor, Codex). Scope of exposure: 2,388 organizations identified — ranging from a $250B enterprise down to solo developers. The Cloud Security Alliance published a CSA Research Note on the same day. Sentry acknowledged disclosure on June 3 and patched the specific payload string found during testing — but not the architectural pathway that makes injection possible in the first place.

**Why it matters:** Leo's fiction pipeline doesn't use Sentry today, so this is a low-immediate-threat for him. But as his tooling scales — adding more MCP integrations, more external error sources, more monitoring tools — the attack surface grows. The lesson is structural: any MCP tool that ingests third-party content (error trackers, ticketing systems, log aggregators) is a potential injection surface. Every external MCP input should be treated as untrusted until validated. This is different from last week's Claude Code GitHub Action CVE — that was a known CVE. Agentjacking is a new attack class.

**Build verdict:** INFORMATIONAL — the specific exploit is patched; the architectural lesson applies to how Leo structures future MCP chains.
🔗 https://tenetsecurity.ai/blog/agentjacking-coding-agents-with-fake-sentry-errors/

### 3. arxiv:2606.08162 — Silent Failure in LLM Agent Systems: The Entropy Principle
**Source:** arxiv.org · **Score:** 7/10

Dexing Liu analyzed 40,000+ controlled trials and 100,000+ production observations to document a specific category of agent failures: **silent failures** — unexpected deviations from intended behavior that occur under normal conditions, without external attack, without resource exhaustion, without visible error. These failures are routinely misattributed to bugs or configuration errors. The paper's core claim: they're not defects; they're the inevitable consequence of 22 intrinsic properties of language-based autonomous systems across six lifecycle layers (foundation semantics, inter-agent transmission, memory persistence, task execution, feedback correction, systemic evolution).

The "Entropy Principle": information integrity degrades monotonically during long agent runs. Each context compression, each memory injection, each tool call summary introduces small distortions. Over many turns, distortions compound. The agent drifts from its original mandate without knowing it's drifting. The paper proposes "PIG+ADE" countermeasures from production practice — Probe-Inject-Guard + Assertion-Driven Execution — as the structural antidote.

**Why it matters:** This is a precise description of what happens to Leo's overnight novel runs when they "just go wrong" after hour 4. The drift isn't random — it's systematic entropy in the feedback correction and memory persistence layers. The countermeasures (explicit probing to verify agent state, assertion-driven task execution) suggest Leo should add mid-run state verification checkpoints to his fiction pipeline: every N chapters, the orchestrator runs an explicit "does current output match original plot outline?" probe before continuing. This is cheaper than restarting from scratch when you notice chapter 12 went off the rails.

**Build verdict:** INFORMATIONAL — paper establishes the framework; the PIG+ADE implementation requires reading the full paper. High-value foundation for the eventual `/book-pipeline` skill architecture.
🔗 https://arxiv.org/abs/2606.08162
