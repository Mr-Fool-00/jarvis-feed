### 1. Statewright — Visual State Machines That Make AI Agents Reliable
**Source:** github.com/statewright/statewright · Show HN (hn:48108778) · **Score:** 8/10
A Rust state machine engine that constrains which tools your Claude Code agent can access per workflow phase. Instead of handing an agent 40+ tools at once, you define phases (Plan → Implement → Test → Review) and the engine enforces which tools are allowed in each. Integrates via MCP and hooks. A phase-constrained tool architecture directly attacks this. The Apache 2.0 core is safe to build from. We don't need their cloud; we can implement the concept as a hook/skill combination.
**Build verdict: BUILDABLE — phase-constrained tool access is the missing layer in your writing pipeline. Briefing filed to #improvements.**

### 2. HASP — Harnessing LLM Agents with Skill Programs
**Source:** arxiv:2605.17734 (NYU + Salesforce AI Research) · **Score:** 7/10
HASP upgrades Claude Code skills from passive text advice into **executable Program Functions (PFs)** — guardrails that activate on failure-prone states and inject corrective context directly into the agent loop. Skills go from "here are instructions" to "here is a function that fires when condition X is detected and pushes the agent back on track." Three deployment modes: inference-time intervention, post-training supervision, and self-improvement loops.
**Why it matters:** Your skills currently tell Claude what to do; they don't catch it when it drifts. HASP's architecture turns skills into active enforcers. The inference-time mode is the most Leo-relevant — it could be approximated as a hook that monitors agent output quality and fires corrective prompts before the next turn.
**Build verdict: INFORMATIONAL — architecture concept with no ready-made build shape for today. Worth a re-read after Statewright is working.**
🔗 https://arxiv.org/abs/2605.17734

### 4. SkillOps: Managing LLM Agent Skill Libraries as Self-Maintaining Software Ecosystems
**Source:** arxiv:2605.13716 (Hongji Pu et al., May 13, 2026) · **Score:** 6/10
Frames skill libraries as code with "technical debt" — skills accumulate defects as they're added, patched, and linked to changing dependencies. Introduces typed Skill Contracts (Precondition / Output / Action / Validation / Failure), Hierarchical Skill Ecosystem Graph, and observable-rule-driven maintenance. Near-zero LLM calls for library maintenance (Rust rule engine). Achieves 79.5% task success on ALFWorld, +8.8pp over strongest baseline.
**Build verdict: INFORMATIONAL — ahead of where your skill library is today. Check back when you hit 100+ skills.**
🔗 https://arxiv.org/abs/2605.13716

### 5. TriMem: Beyond Atomic Facts in Lifelong LLM Agent Memory
**Source:** arxiv:2605.19952 (Jingwei Sun et al., May 19, 2026) · **Score:** 6/10
Proposes three simultaneous memory representations: raw dialogue segments (storage fidelity), extracted atomic facts (fast retrieval), and synthesized profiles (holistic reasoning). Most existing agent memory just collapses dialogue to facts — TriMem keeps all three layers alive simultaneously. Relevant to anything that needs to maintain character consistency or world-state across chapters.
**Build verdict: INFORMATIONAL — no obvious build shape yet. Would become relevant if you start building persistent-state memory for your writing pipeline.**
🔗 https://arxiv.org/abs/2605.19952
