### 2. When Safe Skills Collide: Measuring Compositional Risk in Agent Skill Ecosystems
**Source:** arxiv:2606.00448 · **Score:** 7/10
SkillReact tests pairs of **individually-safe** skills from ClawHub. Out of 211,575 pairs formed from 651 skills that each passed individual inspection, **22.25% have structural compositional risk** — meaning a combined skill set behaves unsafely even when each component is safe. The framework has three layers: static composition benchmark, LLM-assisted human-adjudication pipeline, and an action-based exploitability harness.
**Why it matters:** Every Jarvis recommendation that involves installing multiple skills carries an unchecked compositional risk right now. The runbook's Step 4.5 safety gate checks each skill individually — this paper proves that's not enough. If Leo builds a fiction pipeline with 5-10 skills loaded simultaneously, the interactions between them haven't been audited. Direct relevance to the `/book-pipeline` architecture: we need to gate-check skill combinations, not just individual skills.
Build verdict: INFORMATIONAL — paper, no code, but the implication (audit skill pairs before recommending multi-skill setups) should update Step 4.5
🔗 https://arxiv.org/abs/2606.00448

### 3. SkillHarm: Lifecycle-Aware Skill-Based Attacks via Automated Construction
**Source:** arxiv:2606.02540 · **Score:** 7/10
SkillHarm introduces a benchmark covering skill-based attacks across the **full skill lifecycle** (discovery, installation, execution, update, removal) with a systematic taxonomy of skill-relevant risks. Unlike prior work that tested poisoned skills within a single task, SkillHarm demonstrates that attacks can be embedded at any stage — including in updates to skills that were clean at install time. Authors: Ning, Zhang, Lal, Gou, Li, Ruan, Ye, Gupta, Yang, Su, Sun.
**Why it matters:** The "update-stage attack" finding is the most practically alarming: a skill Leo approves today could be weaponized in an update tomorrow. This reinforces the Jarvis rule of building our own versions vs. installing third-party skills — if we own the code, updates only happen when we push them.
Build verdict: INFORMATIONAL — strengthens existing safety gate reasoning, no immediate action needed beyond continuing the no-auto-install rule
🔗 https://arxiv.org/abs/2606.02540
