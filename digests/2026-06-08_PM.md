Supports 37 built-in web novel genres. Anti-AI-detection pass and multi-dimensional review (plot hooks, coherence, pacing, character voice, continuity) built into the write pipeline. Tested to 2,000,000 characters without continuity collapse.

At 15-hour novel pace (10-15 books this summer), context blowout and consistency failures compound across chapters. webnovel-writer's commit-per-chapter + hybrid retrieval is the direct solution. The `/webnovel-query` command (look up a character's last-known location, a foreshadowing thread, any relationship) is the "world bible as database" pattern that makes 100+ chapter novels coherent. **Build verdict: BUILDABLE** — it's third-party GPL code, so Jarvis won't install it. ### 2. CC v2.1.166 — fallbackModel setting + cross-session security hardening
**Source:** github.com/anthropics/claude-code/releases/tag/v2.1.166 · **Score:** 8/10

Released June 6, 2026. The two headline changes:

**fallbackModel** — new settings.json key that chains up to 3 fallback models tried in order when the primary is overloaded or unavailable. Config: `"fallbackModel": ["claude-sonnet-4-6", "claude-haiku-4-5"]`. Applies to both interactive sessions and `--fallback-model` flag. Backgrounded sessions (`/bg`, `←detach`) preserve the fallback chain. Claude Code retries a turn once on the fallback model when the API rejects an unexpected non-retryable error; auth, rate-limit, request-size, and transport errors still surface immediately (no silent failovers on billed errors).

**Cross-session messaging hardening** — messages relayed via SendMessage from other Claude sessions no longer carry user authority. Receivers refuse relayed permission requests. Auto mode blocks them entirely. Direct response to the "Comment and Control" class of attacks (covered June 5 — PR title injection causing full credential dump) where injected content in one session attempted to elevate trust in another.

Also in this release: glob pattern support in deny rules (`"*"` denies all tools), `MAX_THINKING_TOKENS=0` now correctly disables thinking on default-thinking models.

**Why it matters:** Leo runs book pipelines overnight/AFK. Without fallbackModel, a single Opus overload kills the run. The June 5-6 outage was real — Opus 4.7/4.8 were down for ~6 hours. With fallbackModel in place, the pipeline degrades to Sonnet and keeps writing instead of dying at 2 AM. 3-line settings.json change. The cross-session hardening also matters if Leo ever has multiple Jarvis sessions running simultaneously — injected agent messages can no longer escalate their own permissions. **Build verdict: BUILDABLE** — literally a settings.json config update. Briefing in #improvements with exact config.

🔗 https://github.com/anthropics/claude-code/releases/tag/v2.1.166

### 3. datasette-agent-edit v0.1a0 — surgical str_replace/view/insert as the minimal agent file-editing API
**Source:** simonwillison.net/2026/Jun/7/datasette-agent-edit/ · **Score:** 7/10

Simon Willison released datasette-agent-edit on June 7, 2026 — a storage-agnostic file-editing plugin for Datasette Agent. The plugin provides three tools: **view** (show a section of a file with line numbers), **str_replace** (find an exact old string and replace it with a new string — fails if the string appears more than once), and **insert** (insert specified text after a specified line number). It's designed to be a base plugin so any other plugin that needs file editing — collaborative Markdown editing, updating large SQL queries, editing SVG files — can extend it rather than re-implementing the primitives. Willison built it because "these three operations cover essentially every file-editing scenario an agent needs without giving it the foot-gun of write-the-whole-file."

**Why it matters:** Leo's writing pipeline currently edits chapter files via full rewrites. For a 10,000-word chapter, a full rewrite on a small fix is both slow and risky (entire file overwritten on any error). The str_replace/view/insert triad is the pattern that replaces full rewrites with surgical edits: agent views the relevant section, finds the exact passage, and replaces only that. This is exactly how the Edit tool in Claude Code works internally — it's a validated pattern. Building this natively for Leo's chapter-editing skill is straightforward and safe. **Build verdict: BUILDABLE** — not the Datasette plugin (won't install Datasette), but the pattern. Briefing in #improvements with sketch of a native chapter-edit skill using these three primitives.

🔗 https://simonwillison.net/2026/Jun/7/datasette-agent-edit/
