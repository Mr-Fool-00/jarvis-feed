### 2. CC v2.1.210 — Security Hardening: Worktree Isolation + Agent Anti-Injection + Ultracode Fix
**Source:** github.com/anthropics/claude-code/releases · **Score:** 8/10

Released July 14 at 23:45 UTC. Three separate security/reliability fixes that matter for Jarvis specifically.

**Security fix 1 — Worktree isolation:**
`isolation: 'worktree'` subagents could previously run git-mutating commands against the main repo checkout, not their isolated worktree. Now hardened. If you use worktree isolation in any multi-agent workflow, this is a silent bug that was letting subagents modify the main branch.

**Security fix 2 — Agent tool indirect prompt injection:**
The Agent tool is now hardened against indirect prompt injection via content a subagent READ. Concretely: if a subagent reads a malicious file or web page containing injected instructions, those instructions no longer propagate to the parent agent's tool calls. This matters for Jarvis: the discovery loop reads external web content; this fix means a malicious page can't hijack the parent session.

**Ultracode keyword fix (Jarvis-specific):**
The `ultracode` keyword opt-in was firing on non-human-originated input — webhook payloads, relayed PR comments. Jarvis subscribes to GitHub PR events. Without this fix, a PR comment containing the word "ultracode" would accidentally trigger the ultracode workflow in Jarvis's session. Now fixed.

**Other notable fixes:**
- MEMORY.md writes that would exceed read limit now produce an explicit error instead of silently truncating — prevents Jarvis's memory files from corrupting silently.
- Sonnet 5 now set as default permission classifier for external sessions.
- Fixed killed background sessions leaving permanent git worktree locks.
- Fixed hook callback timeout being misreported as user rejection (stops Jarvis from stalling on hook timeouts).
- Hardened auto mode: destructive git commands blocked when you didn't ask to discard local work.
- Improved dataviz skill's chart color validation (OKLab perceptual distance + recalibrated colorblindness thresholds).
- Memory writes that would push MEMORY.md over its read limit now produce an explicit error instead of silently truncating.
- Fixed unmatched `$1`/`$2` positional placeholders in skills/commands being silently stripped — now preserved verbatim.

**Why it matters to Leo:** The ultracode webhook fix directly affects Jarvis. The Agent tool anti-injection fix means Jarvis can read external web content without risk of the content hijacking the session. These are real-world attack vectors that this run closes.

### 3. StructAgent (arxiv:2607.11388) — Causal State Tracking for Long-Horizon Agent Tasks
**Source:** arxiv.org/abs/2607.11388 · **Score:** 7/10

Published July 13, 2026. Authors: Wenyi Wu, Sibo Zhu, Kun Zhou et al.

**The problem it solves:** Long-horizon agent tasks (multi-chapter fiction, multi-phase coding, complex research) accumulate raw interaction history that makes task progress hard to verify or recover. When something goes wrong in chapter 14, the agent has no clean way to know *what* changed vs what was established, or which earlier state to roll back to.

**What StructAgent does:** Introduces a unified causal representation of task progress — essentially a state machine with verifier-backed transitions. Rather than reasoning over raw transcript history, the agent tracks:
- What facts are CONFIRMED (established and verified)
- What is IN PROGRESS
- What has FAILED (with root cause)
- Causal dependencies between states (this chapter requires that world-state)

State transitions are validated by a verifier before they are committed, preventing the agent from assuming progress that didn't happen.

**Relevance to Leo's fiction pipeline:** This is exactly the architectural pattern missing from most automated chapter-generation runs. A StructAgent-style tracker could maintain:
- Chapter-level state: drafted / revised / continuity-checked / approved
- World state nodes: character locations, faction standings, revealed plot facts
- Causal edge: "chapter 12's revelation REQUIRES world-state established in chapter 8"

When the pipeline drifts or halts, the state graph tells you exactly where and why.

**Why it matters:** This is the cleanest formalization of the problem Leo's writing pipeline hits in practice. The paper doesn't require a specific model — the pattern is architecture-level.

**Build verdict: INFORMATIONAL — research framework; not yet directly skill-shaped into a CC command. Keep for when Leo designs the inter-chapter state management layer of the fiction pipeline.**

🔗 https://arxiv.org/abs/2607.11388

### 7. STRACE: Causal Agent Optimization from Failure Traces (arxiv:2607.07702)
**Source:** arxiv.org/abs/2607.07702 · **Score:** 5/10
From Chinese Academy of Sciences / Microsoft Research (July 8). The problem: reflection-based agent optimization fails because large trace collections are redundant and individual trajectories contain causally irrelevant steps. STRACE builds a textual dependency graph over each trace, mines failure patterns at batch level, then localizes root-cause modules within individual traces. On VeruSAGE-Bench: 1.4× success rate improvement (42.5% → 58.5%). For Leo: when a fiction pipeline run fails at chapter 8, STRACE-style analysis tells you WHY and which agent caused it — not just "it failed here."
🔗 https://arxiv.org/abs/2607.07702

### 8. AgenticSTS: Bounded-Memory Testbed for Long-Horizon Agents (arxiv:2607.02255)
**Source:** arxiv.org/abs/2607.02255 · **Score:** 5/10
Published July 2 (surfaced late due to arxiv 403 in sandbox). Uses Slay the Spire 2 as the testbed — hundreds of sequential decisions, closed rules, clear evaluation. Core idea: **memory as a typed contract**. Instead of appending raw cross-decision transcripts, each decision's prompt is assembled from typed retrieval, keeping context bounded regardless of run length. Any single memory layer is independently ablatable. The architecture maps directly to long-form writing: world state, character sheets, plot facts, and style constraints should be typed retrieval inputs — not inline context.
🔗 https://arxiv.org/abs/2607.02255
