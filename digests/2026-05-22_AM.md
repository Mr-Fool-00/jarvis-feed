### 1. Addy Osmani — Long-running Agents
**Source:** addyosmani.com/blog/long-running-agents · **Score:** 8/10
Osmani lays out five hard-won patterns for agents that actually survive multi-session work: (1) Checkpoint-and-Resume (write intermediate state to disk, recover from disk on boot), (2) Handoff File / Session Bridge (structured summary file that's ALL the next session needs — not a chatty summary, a machine-readable state handoff), (3) Context Reset as First-Class Operation (compaction isn't enough for very long jobs — tear down the session, rebuild from the handoff file), (4) Separate Generation from Evaluation (planner/worker/judge, not one agent doing everything), (5) Append-Only Event Log (makes the agent recoverable, debuggable, auditable).  The piece was written with Shubham Saboo and maps directly to Anthropic's `cwc-long-running-agents` repo patterns.

**Why it matters:** Your writing pipeline runs as multi-session Claude work — chapters don't finish in one context window. Right now, each chapter session starts cold. Implementing Pattern 2 (Handoff File) as a `/checkpoint` skill would let each session hand off to the next with structured state: chapter number, narrative threads open, last voice-DNA calibration, next scene beat. The result: sessions that feel continuous instead of amnesiac. This is the harness improvement your pipeline needs most right now.

**Build verdict: BUILDABLE** — I can implement a `/checkpoint` skill that writes a structured `handoff.md` at session end → read by the next session's CLAUDE.md hook. No third-party installs. Pure Leo-owned code.

### 2. Self-Improving Claude Code — The Pattern
**Source:** towardsdatascience.com (May 15, 2026) · **Score:** 8/10
A TDS article by a practitioner who set up a two-track improvement system for their Claude Code: (Track A) a nightly cron runs a Claude session that scans the last 24h of session JSONL logs, identifies corrections and inefficiencies, extracts general patterns ("don't patch widely-used infrastructure"), and appends structured rules to `~/.claude/CLAUDE.md`. (Track B) manual interaction improvements — how they phrase asks, when they interrupt vs. let it cook. Together: cumulative improvement that compounds weekly. The key mechanic: Claude reads CLAUDE.md at session start, so every correction immediately takes effect in future sessions. Companion piece is TDS's "How to Make Claude Code Improve from its Own Mistakes" and Addy Osmani's January post on the "Ralph Wiggum" self-improvement loop (iterative agent loop that refines acceptance criteria from failures).

**Why it matters:** Jarvis already does macro-level learning (reactions.md, feedback.md feed into discovery scoring). This is the MICRO equivalent: individual writing sessions and build sessions that improve your Claude Code's behavior over time without you manually editing CLAUDE.md. The pattern is simple enough to implement as a Claude Code Routine (scheduled task) that runs at midnight on your machine, scans session logs, and silently updates your CLAUDE.md. The compounding is real — practitioners report Claude making noticeably fewer repeated mistakes within a week.

**Build verdict: BUILDABLE** — implementable as a nightly Claude Code Routine (no third-party dependencies). The skill needs: read JSONL session logs → extract correction patterns → format as CLAUDE.md rules → append with dedup check.

### 3. BayramAnnakov/claude-reflect — Self-Learning Hook System
**Source:** github.com/BayramAnnakov/claude-reflect · **Score:** 8/10
1,000 stars, 88 forks, active through February 2026. A two-part system: (Stage 1) hooks monitor Claude Code sessions and automatically queue potential learnings when they detect correction patterns — using regex + AI semantic analysis, with confidence scores 0.60–0.95. (Stage 2) you run `/reflect` which presents a review table where you approve, skip, or edit each queued learning before it syncs permanently to `~/.claude/CLAUDE.md` and `.claude/commands/`. The v2 `/reflect-skills` command goes further: analyzes session history for repeating patterns ("you asked for X review 15 times") and auto-generates draft skills. Essentially automates the TDS pattern from Item 2 with a review gate.

**Why it matters:** If the Item 2 pattern is the concept, this is a production-ready implementation of it. The review gate is smart — you don't blindly trust what the agent thought it learned, you eyeball the table and approve. 1K stars in a field with lots of noise means real practitioners are using it.
