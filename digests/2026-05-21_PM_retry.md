### 1. anthropics/cwc-long-running-agents — Official harness primitives for long-running agents
**Source:** github.com/anthropics/cwc-long-running-agents · **Score:** 9/10

Official Anthropic repo, 102 stars, open-sourced from Code with Claude 2026. Ships three standalone hook files + a subagent definition that together solve the two hardest problems in multi-session agentic work: premature success claims and context-window resets.

**Three core primitives:**
1. **Default-FAIL Contract** (`verify-gate.sh`) — every feature criterion starts `false`. A `PreToolUse` hook blocks the agent from writing a passing result until it has opened and read the actual evidence. "Asking nicely in the prompt doesn't reliably stop this."
2. **Fresh-Context Evaluator** (`agents/evaluator.md`) — a separate subagent invoked with `claude --agent evaluator -p "..."` that has no Write/Edit tools and never saw the build context. Grades independently. Returns `PASS` or `NEEDS_WORK`.
3. **Agent-Maintained Handoff** (`PROGRESS.md` + `commit-on-stop.sh` hook) — agent writes progress before each session ends. A backstop hook commits any uncommitted work at stop. Next session reads `PROGRESS.md` first. Context-window reset ≠ lost work.

Plus two operator-control hooks: `kill-switch.sh` (halts all tool calls while a file exists) and `steer.sh` (reads a `STEER.md` file mid-run to redirect without restart).

Works with either `/goal` (built-in) or a simple `while grep -q '"passes": false' test-results.json; do ...` loop.

**Why it matters:** Leo's writing pipeline currently relies on *prompting* to stop early "I'm done!" claims (`do not mark as complete unless all verify-15 criteria are met`). That's fragile. The Default-FAIL Contract makes it structural — Claude literally cannot mark a chapter as passing without reading the evidence that it passed. The Fresh-Context Evaluator is exactly what verify-15 should be: a separate clean-context agent that never touched the draft doing the grading. The PROGRESS.md handoff solves the context-rot problem in long book sessions. This is a weekend build that would materially harden Leo's pipeline.

**Build verdict: BUILDABLE** — adapt these three hooks (verify-gate, evaluator subagent, commit-on-stop) to the writing pipeline. The code is already written; it's an integration job.

🔗 https://github.com/anthropics/cwc-long-running-agents

### 2. Claude Code v2.1.146 — /code-review with effort levels (today)
**Source:** Claude Code changelog, code.claude.com/docs/en/changelog · **Score:** 7/10

Released May 21, 2026 (today). Two changes worth knowing:

**`/simplify` → `/code-review` with effort levels.** The command is renamed to `/code-review` and now accepts `low`, `medium`, or `high` as an argument (e.g. `/code-review high`). High effort = deeper structural analysis; low = quick lint-style pass. This makes code review a first-class graduated action rather than an all-or-nothing call.

**Auto-mode no longer suppresses `AskUserQuestion` when skill/user relies on it.** This was a quiet but annoying bug: if a skill explicitly called `AskUserQuestion`, auto-mode would suppress the prompt and the skill would silently fail or skip the question. Now it respects the explicit call. Affects all Routines-style skills that need a human checkpoint mid-task.

Additional bug fixes: Windows PowerShell `pwsh` path resolution, MCP paginated resources/templates/prompts dropping items past page 1, full-screen strobing in Windows Terminal background sessions.

**Why it matters:** The `AskUserQuestion` fix directly affects Jarvis. The Discovery Loop Routine uses `AskUserQuestion`-style gates in several places. Previously those could be silently swallowed in auto-mode. Now they work. The `/code-review high` effort level is useful for Leo's Jarvis dev sprints as a quality gate before committing.

**Build verdict: INFORMATIONAL** — changelog update, no skill to build. But apply the AskUserQuestion fix awareness to any Routines-based skills that rely on mid-task human checkpoints.

🔗 https://code.claude.com/docs/en/changelog

### 3. Neil Kakkar: "How I'm Productive with Claude Code"
**Source:** neilkakkar.com · HN: 47494890 · **Score:** 7/10

Production developer's detailed breakdown of what actually works in daily Claude Code use. Three patterns worth extracting:

**`/git-pr` skill** — reads the full git diff and writes the PR description automatically. Neil built this as his first Claude Code skill. The time savings are real, but the real unlock was removing the context-switch of stopping to write descriptions. Concrete: 10 minutes to build, trivial to install, works on every repo.

**Multi-agent comparison** — for a new feature, he spins up 2-3 agents that each implement it independently from scratch, then reviews all outputs together. The cross-implementation comparison surfaces design decisions he wouldn't have seen with a single pass. He uses his informed judgment on the hybrid. This is "best-of-N" at the feature level.

**Review-checklist abstraction** — gets agents to review his code, then abstracts the review feedback into reusable guidelines ("don't use global state for X, always wrap Y in Z"). These guidelines then prime future agents during code review. The checklist self-improves over time as new patterns are caught. This is exactly how Leo's verify-15 should grow: each fixer should be logging its catches, and those logs should feed back into the prompt.

**Why it matters:** The review-checklist abstraction is the highest-leverage pattern here for Leo's writing pipeline. Currently verify-15 catches are lost after each chapter. Building a `/refine-fixers` skill that reads recent verify-15 run logs and proposes prompt improvements would compound the quality of the fixer chain over time. This is a distinct build from anything in the current pipeline.

**Build verdict: BUILDABLE** — `/refine-fixers` skill: read recent fixer-chain logs, surface recurring failure patterns, propose updated fixer prompts. Leo approves each change. The fixer chain gets smarter over 20 chapters instead of staying static.

🔗 https://neilkakkar.com/productive-with-claude-code.html
