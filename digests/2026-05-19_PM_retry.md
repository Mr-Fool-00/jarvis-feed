### 2. Using Claude Code: The Unreasonable Effectiveness of HTML — Simon Willison (May 8, 2026)
**Source:** simonwillison.net · **Score:** 8/10

Thariq Shihipar (Claude Code team at Anthropic) switched from requesting Markdown to requesting HTML as his default output format from Claude agents — and it's worth doing the same. The reasoning: HTML artifacts are what humans actually open, read, and share. Claude can embed SVG diagrams, interactive tabs, in-page navigation, visual structure, collapsible sections, and illustrations in a way that flat Markdown can't. The artifact becomes something worth looking at, not just text to parse.

Practical prompt pattern: `"Help me review this PR by creating an HTML artifact that describes it."` You get a navigable, visual document instead of a flat bullet list.

HN discussion at 48071940 had useful comments: the pattern works best for **deliverable artifacts** (reports, chapter reviews, world-bible summaries, session outputs) rather than quick back-and-forth. For intermediate steps in an agent chain, Markdown is still faster. Use HTML when the output is something Leo will read, not just a step another agent will consume.

**Why it matters:** Your Council skill's output is currently flat Markdown — advisors give responses, chairman summarizes, all in plain text. Switching the final synthesis step to HTML output would give you a visual, navigable session report you'd actually want to open after the session. Same for your chapter-drafter pipeline: the final chapter review could be an HTML document with per-section annotations. Zero workflow change required — just add "return your analysis as an HTML document" to the output prompt.

🔗 https://simonwillison.net/2026/May/8/unreasonable-effectiveness-of-html/

### 3. Claude Code Changelog — Fast Mode → Opus 4.7 + Agent Flags + SKILL.md Fix (May 14, 2026)
**Source:** code.claude.com/docs/en/whats-new + github.com/anthropics/claude-code/releases · **Score:** 7/10

Multiple shipping in one update:

- **Fast mode defaults to Opus 4.7** (was 4.6). Fast mode delivers 2.5x higher token throughput at identical quality. On Max plan this is flat-rate — you get Opus 4.7 speed without paying the API 6x fast-mode surcharge.

- **New `claude agents` flags for dispatched background sessions:** `--add-dir`, `--settings`, `--mcp-config`, `--plugin-dir`, `--permission-mode`, `--model`, `--effort`, `--dangerously-skip-permissions`. These let you configure subagents dispatched in Agent Teams with per-agent model, effort level, and tool scope — the infrastructure for the Council pattern to run each advisor with a different effort setting (high for the chairman, medium for routine advisors).

- **SKILL.md at root level now surfaces as a skill** even without a `skills/` subdirectory. This is a direct improvement for Jarvis: skills/plugins that have a single root SKILL.md no longer need the full directory structure to be recognized by Claude Code.

- **CLAUDE_CODE_PLUGIN_PREFER_HTTPS** env var: clone GitHub plugin sources over HTTPS instead of SSH. Relevant for CCR (cloud) environments where SSH keys aren't available — like this sandbox.

**Why it matters:** The SKILL.md fix directly affects any future Jarvis skill packaging. The `--effort` per-agent flag is the missing piece for giving your Council chairman's synthesis step a `max` effort while keeping the initial advisor passes at `high` (saves quota). And fast mode on Opus 4.7 flat-rate means `/fast` now gets you the best model at 2.5x speed, no extra charge. Enable all three today.

🔗 https://code.claude.com/docs/en/whats-new
