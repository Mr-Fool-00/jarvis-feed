### 1. Anthropic Engineering: Effective Context Engineering for AI Agents
**Source:** anthropic.com/engineering · **Score:** 8/10
Official Anthropic engineering blog post on designing context for production agents. Core argument: most agent failures are context failures, not model failures. The piece covers: just-in-time context loading vs. upfront dumping (load only what the current step needs, not the whole project), active compaction (summarize earlier turns before they push relevant content out of the window), and tool clearing (remove tools whose results are no longer needed in subsequent steps). The headline stat: agents without project context files succeed on complex tasks ~30% of the time; with well-crafted, surgically loaded context files, success reaches ~90%.

**Why it matters:** Leo's chapter writer skill almost certainly loads everything upfront — full world bible, all character sheets, prior chapter summaries, style guide — in one shot at session start. That's the failure pattern this piece is targeting. Just-in-time loading means: at outline step, load only the story structure + arc; at draft step, load the outline + the 2 nearest prior chapters + the voice guide; at revision step, load the specific problem passage + the critique. The context the agent sees at each step is different, purpose-built, smaller. This is a direct pipeline redesign project. The Anthropic Engineering source is authoritative and the technique is tested at production scale.

🔗 https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
**Build verdict: BUILDABLE — redesign chapter writer to use per-step context loading; this is the next skill upgrade after the Outcomes quality gate from AM run**

### 3. Context Engineering Maturity Model — arxiv 2603.09619
**Source:** arxiv.org (March 2026, Vera Vishnyakova) · **Score:** 6/10
"Context Engineering: From Prompts to Corporate Multi-Agent Architecture" proposes a maturity model for how teams evolve their AI system design — from stateless chatbot prompting through context engineering (CE) to specification engineering (SE). The heart of it: five quality criteria for evaluating any piece of context you load into an agent: **relevance** (does the agent need this for this step?), **sufficiency** (does it have everything the current step requires?), **isolation** (does it contaminate adjacent agents or steps?), **economy** (is it the minimal footprint that does the job?), and **provenance** (does the agent know where it came from so it can weight it appropriately?). Draws from Google ADK, Anthropic, LangChain, and Deloitte/KPMG enterprise patterns.

**Why it matters:** Leo's chapter writer doesn't currently score its context inputs against any criteria. Run each piece of context the writer skill loads — world bible, character file, prior chapter, style guide, the task prompt itself — through the five criteria checklist and you'll immediately find what's over-loaded (fails economy), what's missing (fails sufficiency), and what's polluting the agent's reasoning by being there at all (fails isolation). The arxiv paper is the theory layer behind the Anthropic Engineering piece (#1 above). Together they're the complete picture.

🔗 https://arxiv.org/abs/2603.09619
**Build verdict: INFORMATIONAL — use as a scoring rubric for the context redesign in #1; no standalone skill to build**
