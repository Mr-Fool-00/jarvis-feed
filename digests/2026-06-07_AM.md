### 1. Claude Code Channels — Push external events into a running session
**Source:** Anthropic official docs (code.claude.com/docs/en/channels) · **Score:** 9/10
Claude Code Channels lets any MCP server push events INTO a running Claude Code session from outside. You point a channel plugin at Telegram, Discord, or iMessage, and messages from those platforms arrive as live events inside your session — Claude can read them and reply back through the same channel. The security model is strict: an allowlist controls which sender IDs can push events, and `--channels` must explicitly name active servers. Official Anthropic docs are live; community has already built Slack adapters (retrodigio/claude-channel-slack, jeremylongshore/claude-code-slack-channel).

**Why it matters:** This directly solves Jarvis's current architectural hack. Right now the `notify:`, `digest:`, `briefing:` commit-prefix bridge routes Slack messages because direct webhook POSTs are blocked from the CCR sandbox. With a Channels-based Slack plugin, a running Jarvis CCR session could receive incoming Slack reactions and events in real-time — no commit roundtrip, no GitHub Actions latency. Leo's P4 calendar nag system and the Slack DM integration both become significantly simpler to build. **Build verdict: BUILDABLE** — this changes Jarvis's notification architecture. Briefing in #improvements.

🔗 https://code.claude.com/docs/en/channels

### 3. Graph-of-Skills: Dependency-Aware Structural Retrieval (arxiv:2604.05333)
**Source:** arxiv.org · **Score:** 7/10
When a skill library grows into the hundreds, dumping all of them into context saturates the window and degrades accuracy. Graph-of-Skills (GoS) solves this: it builds a dependency graph of your skill library offline, then at inference time retrieves a bounded, dependency-complete skill bundle via hybrid semantic-lexical search + Personalized PageRank. The key insight: fetching `skill-A` without its upstream `skill-B` dependency produces an incomplete bundle that fails at runtime. GoS closes that gap. Open-sourced on GitHub: github.com/davidliuk/graph-of-skills.

**Why it matters:** Leo's skill library is growing. SWE-Skills-Bench (March 2026) showed 80% of skills produce zero improvement when loaded generically — the problem is undiscriminating loading, not the skills themselves. GoS is the architectural answer: smart selective loading that pulls in exactly the skills AND their dependencies needed for the task. When Leo's pipeline reaches 50+ skills, this pattern is directly applicable. **Build verdict: INFORMATIONAL** — research paper with open code, but Leo's library isn't yet at the scale where building this provides day-one ROI.

🔗 https://arxiv.org/abs/2604.05333
