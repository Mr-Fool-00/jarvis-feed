### 1. ⚠️ AgentBaiting — 800+ Fake MCP/Skill Repos Delivering SmartLoader Malware
**Source:** Island Security / HN:48583928 (July 20) · **Score:** 9/10

Island Security documented 7,600+ malicious GitHub repos — 800+ posing specifically as AI Skills and MCP servers — delivering SmartLoader malware through a technique they called "AgentBaiting." The attack surface is distinct from traditional supply-chain attacks: **an agent given a prompt like "find me a free cinematic prompt skill and give me install instructions" independently discovers a FakeGit repo through web search, treats the README as legitimate documentation, and relays attacker-controlled commands to the user.** No phishing link required. Tests confirmed Claude Code, Gemini, and ChatGPT are all vulnerable.

Campaign metrics: 14 million downloads across ~200 repos. Secondary payload: StealC infostealer targeting env vars, AWS keys, GitHub tokens, and developer credentials. The 800+ repos posing as AI Skills/MCPs specifically imitate the naming conventions of legitimate packages (`claude-code-mcp-server`, `anthropic-skill-kit`, etc.).

**Attack mechanics:** Attacker creates convincing README with plausible install instructions (npm/pip/curl). Agent's web search surfaces it. Agent relays the instructions. User's terminal runs the payload. The agent's trust in web search results is the attack vector, not any Claude vulnerability.

**Protective measures until the ecosystem hardens:**
- Do not let Claude autonomously web-search for and install new MCPs/skills — always source from official Anthropic MCP registry or verified publishers with substantial star counts and org backing
- When asking Claude to "find a tool that does X," always review the GitHub profile (org, age, star count, contributor history) before any install step
- Your SAFETY GATE protocol already covers this — this confirms why it's there

🔗 https://news.ycombinator.com/item?id=48583928

**Build verdict: INFORMATIONAL — active threat to your pipeline. No skill to build; the protection is procedural (SAFETY GATE discipline). Consider adding an explicit "never auto-discover MCPs via web search" instruction to your Jarvis persona or relevant skills.**

### 2. CC v2.1.212 — `/fork` Goes Background, `/subtask` Replaces In-Session Subagent, 200-Agent Per-Session Cap
**Source:** github.com/anthropics/claude-code/releases/tag/v2.1.212 (July 17) · **Score:** 9/10

This release (July 17, not caught in AM run) fundamentally restructured how Claude Code forks work. **If you have any existing skill, hook, or mental model that relies on `/fork` for in-session subagent work, it is now broken in a silent way.**

**What changed:**
- `/fork` now copies the current conversation into a new *background session* (visible as its own row in `claude agents`). The main session continues uninterrupted. This is now always background.
- `/subtask` is the new command for "spawn work inside this current session" — the behavior `/fork` used to have for in-session work.
- Per-session subagent spawn cap: defaults to **200** (override: `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`; `/clear` resets the budget).
- Per-session WebSearch limit: defaults to **200**.
- `/resume` now opens an interactive session picker for past sessions.

**Why it matters:**
- Any skill file that calls `/fork` to spin off a research or analysis subagent within a session will now create a detached background session instead. The main session will continue without the subagent's results flowing back inline.
- The 200-subagent cap is a guardrail for runaway fan-out in automated pipelines. If a Jarvis run fans out 200 subagents and hits the cap, subsequent spawns will fail silently unless you've set a higher override.
- Background `/fork` design means Leo can now branch a long-running writing research session without blocking his primary context — useful for "fork this chapter research while I continue outlining" patterns.

🔗 https://github.com/anthropics/claude-code/releases/tag/v2.1.212

**Build verdict: INFORMATIONAL — behavior change, not buildable. Update CC immediately and audit any skill files that call `/fork` expecting inline subagent behavior; replace with `/subtask`.**

### 4. arXiv:2607.16621 — MSCE: Memory and Skills Co-Evolution for Agent Self-Improvement
**Source:** arxiv.org (July 18) · **Score:** 8/10
Training-free framework that **converts successful agent execution traces into callable, versioned skills** — not by training but by pattern-matching: when an agent solves a task with a high-value multi-step trace, MSCE extracts the reusable structure, links it to the evidence (the specific trace that worked), and stores it as a callable skill. Skills are rated by evidence count and recency; low-evidence skills decay. The memory component updates preference models from the same traces. The loop is: run → if success → extract skill → next run uses skill as shortcut. Paper tests on 6 benchmarks, training-free.

**Why it matters to Jarvis:** This is a formalization of "Jarvis learns from its own successful runs." The concept maps directly to a Jarvis improvement: after each digest run, high-quality execution paths (e.g., "how Jarvis found and scored the AgentBaiting story") could be extracted as skill snippets and referenced in future runs. The evidence-linked versioning prevents hallucinated skills from accumulating.

🔗 https://arxiv.org/abs/2607.16621

### 5. Agentjacking via Sentry MCP — Claude Code Hijacked in 85% of Tests via Crafted Error Reports
**Source:** Tenet Security / The New Stack / VentureBeat (June 17 disclosure, resurging July 20) · **Score:** 7/10
Attacker with only a **public Sentry DSN** can inject crafted payloads into Sentry error events. When Claude Code pulls those events via the Sentry MCP server, it interprets attacker text as legitimate remediation steps and executes the instructions — including silent npm package installs. Claude Code hijacked in 85% of test cases. No credentials stolen; every action is "authorized" from the agent's perspective because the MCP output looks like a bug report telling Claude what to fix.

Confirmed same attack surface for Datadog MCP, PagerDuty MCP, and Jira MCP. 2,388 organizations confirmed exposed in Sentry alone.

**If you use Sentry/Datadog/Jira MCPs in any Claude Code session:** treat any MCP output suggesting running external packages or shell commands as suspicious. Mitigation: scope MCP scopes to read-only where possible.

🔗 https://thenewstack.io/agentjacking-sentry-mcp-attack/

**Build verdict: INFORMATIONAL — security awareness. No build needed.**
