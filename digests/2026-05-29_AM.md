### 2. Dynamic Workflows in Claude Code — JavaScript Orchestration, 1,000 Agents, Resumable
**Source:** Anthropic CC Docs · **Score:** 10/10  
Dynamic Workflows launched May 28 (requires CC v2.1.154+, research preview, all paid plans). A **dynamic workflow is a JavaScript script Claude writes for your task** — the runtime executes it in the background, intermediate results stay in script variables instead of Claude's context, and your session stays responsive while agents work.

**What it unlocks:**
- Fans work out to **up to 16 concurrent / 1,000 total subagents** per run
- Subagents adversarially review each other's findings before results are reported
- Runs are **resumable within the same session** — stop/restart without losing completed work
- `/deep-research` is a bundled workflow (multi-angle web search → cross-check → cited report)
- **`ultracode` mode**: set `/effort ultracode` and Claude auto-plans a workflow for every substantive task
- **Save workflows as slash commands** (project `.claude/workflows/` or personal `~/.claude/workflows/`)
- Watch progress live via `/workflows` panel — drill into each agent, pause/restart individual agents

**Proven at scale:** Bun creator Jarred Sumner used Dynamic Workflows to **rewrite Bun from Zig to Rust** — 750,000 lines of Rust, 11 days, 99.8% of the test suite green. Workflow structure: one pass to map every struct field's right Rust lifetime, parallel file-writer agents (2 reviewers each), then a fix loop that ran until build + tests were clean.  
**Why it matters:** This is the primitive you've been missing for your book pipeline. Right now, chapter generation is sequential — each session hands off to the next. Dynamic Workflows lets you say "write a workflow to generate chapters 1–20 in parallel, each with a continuity-checker and voice-DNA-verifier agent, then a final synthesizer that merges the results." The workflow saves as `/write-chapters`. Next time you start a book, you type one command and come back when it's done. The Bun case study proves it handles 750K lines of code — your chapter work is smaller. `/effort ultracode` during a book sprint gives you all of this automatically.  
**Build verdict:** BUILDABLE — `/book-workflow.js` using Dynamic Workflows primitive, parallel chapter writers + adversarial voice/continuity reviewers, save as reusable command. This is the path to the 12-hour novel wall time.  
🔗 https://code.claude.com/docs/en/workflows

### 3. Opus 4.8 API: Mid-Conversation System Messages + Lower Prompt Cache Minimum
**Source:** Anthropic API Docs · **Score:** 8/10  
Two API-level changes ship with Opus 4.8 that matter for any Skill using the Anthropic SDK directly:

1. **Mid-conversation system messages** — you can now inject a `role: "system"` message anywhere after a user turn (no beta header required). This lets you append updated instructions late in a long session **without re-sending the full system prompt**, which preserves prompt cache hits on all earlier turns. Directly cuts input cost on agentic loops where world-state evolves (e.g., "the character now knows X — adjust all subsequent chapters accordingly").

2. **Prompt cache minimum lowered to 1,024 tokens** (was higher on 4.7). Short skill prompts and partial CLAUDE.md sections that couldn't cache before now can — zero code changes required.

Also: `stop_details` object on refusals now publicly documented (was available on 4.7 but undocumented). Better adaptive thinking calibration — model skips reasoning on simple lookups, reasons only when the turn warrants it.  
**Why it matters:** If you have any API-based skill code (the `claude-api` skill, any Council variant using the SDK), the 1,024-token cache floor means you're burning fewer tokens on short system prompts right now. Mid-conversation system messages are the right way to inject state updates in your long-horizon book pipeline — inject the "chapter 12 continuity facts" after every chapter, preserve the cache on everything before it.  
**Build verdict:** INFORMATIONAL — but worth applying in any existing API Skill code that has evolving system-prompt state.  
🔗 https://platform.claude.com/docs/en/about-claude/models/whats-new-claude-4-8
