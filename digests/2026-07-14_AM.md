### 2. MemAgent (arXiv:2507.02259) — RL Memory Agent Extrapolates to 3.5M Context, <5% Loss
**Source:** arxiv.org/abs/2507.02259, github.com/BytedTsinghua-SIA/MemAgent · **Score:** 6/10
**URL:** https://arxiv.org/abs/2507.02259

Published **July 3, 2026** by BytedTsinghua-SIA (joint Bytedance + Tsinghua SIA lab). Released practical models: **RL-MemAgent-14B** and **RL-MemAgent-7B**.

**What it does:**
MemAgent is a multi-conversation RL-trained agent workflow that reads text in overlapping segments, maintains a rolling compressed memory using an overwrite strategy, and passes only the memory (not the full context) between turns.

**Key results:**
- Trained on **8K context** with 32K text
- Extrapolates to **3.5M-token QA tasks** with **<5% performance loss**
- **95%+ on 512K RULER test** (long-context benchmark)
- Extends the DAPO RL algorithm to support end-to-end optimization of agent workflows over multi-turn context-independent conversations

**Why it matters architecturally:** Most long-context approaches require longer-context fine-tunes or RAG chunking with retrieval. MemAgent does neither — it trains a *separate agent* to do compression and memory management, leaving the base model untouched. The segment-read + overwrite approach is novel because it's trained end-to-end via RL rather than hand-designed compression rules.

**Fiction pipeline relevance:** A story-continuity agent for Leo's novel pipeline could use the same segment-read/overwrite pattern — read chapter N, update memory (characters, world state, unresolved threads), pass compressed memory to chapter N+1 generation. The 3.5M extrapolation means it can theoretically hold an entire novel in rolling context without architecture changes to the generation model.

**Practical bar to entry:** Requires running a 14B model or integrating the workflow as a wrapper around a hosted model. No native CC integration. Would need a custom Claude SDK implementation to apply the pattern with Anthropic models.

**Build verdict:** INFORMATIONAL — research paper, no immediate CC integration. The overwrite-memory pattern is worth keeping in mind for the fiction pipeline council architecture. Archive for consideration when designing inter-chapter memory agents.
