### 2. CC Sandbox Credential CVE Chain + v2.1.187 `sandbox.credentials` Fix
**Source:** SecurityWeek / GitHub Security Advisory · **Score:** 8/10
A researcher (handle: @null_byte_0x00) disclosed a SOCKS5 null-byte injection vulnerability in Claude Code's sandboxed Bash environment. The chain: (1) sandboxed Bash commands could reach the SOCKS5 proxy with a null-byte-injected hostname, (2) the proxy mis-routed the request to external endpoints, (3) this allowed exfiltration of credential files (`~/.aws/credentials`, `~/.ssh/id_rsa`, `.env`) and environment variables including `ANTHROPIC_API_KEY`. Affected versions: v2.0.24 through v2.1.89 (approximately 5.5 months). Anthropic patched silently — no CVE was filed publicly, no release notes called it out. SecurityWeek's headline: "Anthropic Silently Patches Claude Code Sandbox Bypass." The fix in v2.1.187: new `sandbox.credentials` config key that blocks credential file reads and env var exposure from within sandboxed tool calls. Not retroactive — you must be on v2.1.187+ for the protection to apply.

**Why it matters:** If you run CC with `ANTHROPIC_API_KEY` in your shell environment (which is almost everyone's setup), and you ran any version between v2.0.24 and v2.1.89, the sandbox didn't fully isolate that key. The attack requires a compromised tool or prompt injection to trigger — but the surface was real. Check your current CC version immediately: `claude --version`. If below v2.1.187, update. Check your `~/.aws/credentials` and `.env` files for evidence of unexpected access. The Jarvis routine itself runs in CCR containers, so the per-run environment is ephemeral — but any PAT or API key in environment variables during a run was potentially in scope during those versions.

🔗 https://www.securityweek.com/anthropic-silently-patches-claude-code-sandbox-bypass/
**Build verdict: INFORMATIONAL — update CC to v2.1.187+; add `sandbox.credentials: true` to your CC config; audit any persistent environments that ran vulnerable versions**
