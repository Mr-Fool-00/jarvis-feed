### 2. MindStudio: Self-Learning Claude Code Skills via Learnings.md
**Source:** mindstudio.ai/blog · **Score:** 7/10  
A simple but powerful pattern: add a `LEARNINGS.md` file to any Claude Code skill. Claude reads it at the start of each task, appends new lessons learned after each run, and the next session starts with that accumulated knowledge already in context. Over time the file builds a record of what approaches work, what causes failures, and what quirks are specific to this project. MindStudio has published a 5-part series on this (Learnings Loop, self-improving workflows, persistent memory systems, four-pattern framework).

**Why it matters:** Jarvis already has `state/feedback.md` and `state/agent_suggestions.md` for inter-run learning. Adding `LEARNINGS.md` to each individual skill is the missing micro-layer — instead of Jarvis self-improving at the session level, each skill self-improves at the task level. The pattern applies immediately to Leo's writing skills: imagine a `write-chapter` skill that remembers "Leo's preferred pacing in action scenes: 2-3 short paragraphs, never longer than 150 words each" because it learned that from a correction three chapters ago. The implementation is 10 minutes: add a LEARNINGS.md file and two lines of instruction to the SKILL.md frontmatter. High ROI, low cost.

🔗 https://www.mindstudio.ai/blog/self-learning-claude-code-skill-learnings-md  
**Build verdict: BUILDABLE — Direct Jarvis upgrade: add LEARNINGS.md to each skill in Leo's `~/.claude/skills/`. Briefing filed.**

### 3. rhavekost/author-toolkit — 5 Editorial Personas for Novel Writing
**Source:** github.com/rhavekost/author-toolkit · **Score:** 7/10  
A Claude Code plugin with 5 specialized editorial personas: Developmental Editor (plot, pacing, structure, stakes), Line Editor (prose rhythm, word choice), Character Consultant (voice consistency, motivation, arc), Continuity Tracker (timeline, world facts, internal consistency), and Brainstorm Partner (what-if exploration, problem solving). Three-stage workflow: build Story Bible → develop chapters with chosen persona → simulate reader testing for emotional resonance.

**Why it matters:** The 5-persona model is a cleaner Council pattern than most writing tools ship — it separates structural editing from prose editing from consistency-checking, which is the right level of granularity for long-form. The Story Bible anchoring means each persona starts with shared world knowledge. The reader-testing simulation is a genuinely novel idea: using an AI persona that simulates a target reader's emotional response, catching "this chapter felt flat" before Leo would have to re-read the whole thing. Complements `howells/fiction` well — `howells/fiction` is pipeline-first, `rhavekost/author-toolkit` is craft-depth-first.
