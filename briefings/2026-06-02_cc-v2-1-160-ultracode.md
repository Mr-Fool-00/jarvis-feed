# CC v2.1.160 — Ultracode Rename + Security — 7/10

## What it is
Claude Code shipped an update today (version 2.1.160). The two things worth your attention: first, the keyword that triggers Dynamic Workflows was renamed from `workflow` to `ultracode`. Second, the tool now asks you to confirm before it writes to certain sensitive files (shell startup files, npm config, etc.).

## Why you'd want to know this (specific to your stack)

**The rename matters for your prompts.** If you have any Claude Code skills, commands, or CLAUDE.md instructions that include the word "workflow" with the expectation that it launches a Dynamic Workflow session — that no longer works. You now need to either use the word "ultracode" or go to /config and enable the ultracode effort setting. 

Worth doing a quick `grep -r "workflow" ~/.claude/` to see if any of your existing commands reference this keyword.

**The security improvement matters for Jarvis.** The new update adds a confirmation prompt before Claude writes to shell startup files (`.zshenv`, `.zlogin`, `.bash_login`) or build tool config files (`.npmrc`, `.yarnrc*`, `.bazelrc`, `.devcontainer/`). This means if a skill or agent tries to slip a command into your shell startup, Claude will stop and ask you first. Good safety improvement for cron/automated environments.

## Why I think it's worth your attention
The keyword rename is a silent breaking change — if you have Dynamic Workflow triggers in your setup, they stopped working today without any warning. Takes 30 seconds to check and fix.

## What to do

1. Run: `grep -r "workflow" ~/.claude/` and check if anything is supposed to trigger Dynamic Workflows
2. If yes, rename those references to `ultracode` (or use `/effort ultracode` at the start of a session)
3. No action needed on the security improvements — they're on by default and helpful
