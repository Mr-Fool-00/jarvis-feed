### 2. "Skill Issues" — A Single Markdown File Gets a Reverse Shell (Reversec)
**Source:** labs.reversec.com · **Score:** 8/10

Reversec's security research team published Part 1 of a series on compromising Claude Code through malicious SKILL.md files. The finding: with out-of-the-box Claude Code settings, a single crafted markdown file successfully obtained a reverse shell in a controlled test. Claude's reasoning layer does catch explicit `rm -rf` commands, but dynamic context injection (executable directives that run before the model reads the skill) bypasses that reasoning entirely.

The analogy the researchers use: sharing a Claude skill file is *functionally equivalent to sharing a random executable* in a world where people treat it like a doc. Thousands of users currently share skill files via GitHub repos with no security review. The research notes no official Anthropic signature or verification step exists between "found on GitHub" and "running in your shell."

**Why it matters:** Jarvis's safety gate exists because of exactly this. Every third-party skill Leo considers goes through deep-dive before briefing. But the scale numbers (Snyk found issues in 36% of 3,984 public skills) mean that casual users across the ecosystem — including people whose workflows Leo might want to reference or borrow patterns from — are running compromised setups. This changes how to evaluate "someone showed me their skill on Reddit" as a signal.
🔗 https://labs.reversec.com/posts/2026/05/skill-issues-compromising-claude-code-with-malicious-skills-agents-part-1

Build verdict: INFORMATIONAL — security research, validates safety gate, no buildable shape from this alone.

### 3. Snyk ToxicSkills — 36.82% of 3,984 Public Skills Have Security Issues
**Source:** snyk.io · **Score:** 8/10

Snyk scanned every public skill in ClawHub and skills.sh as of February 2026. Results: 1,467 skills (36.82%) have at least one security issue; 534 (13.4%) have critical-level issues including malware distribution, SSH key exfiltration, and prompt injection. Named campaign **ToxicSkills** / **ClawHavoc**. Snyk confirmed real-world attacks: three lines of markdown in a SKILL.md instructed agents to read SSH keys and POST them to an attacker's server.

The attack vector is uniquely dangerous: the agent inherits the developer's full permission set (file system, cloud credentials, shell) while simultaneously having its reasoning hijacked via prompt injection. Snyk's remediation advice: treat skills like software dependencies. Review them. Version them. Log invocations.

Snyk also announced a **partnership with Tessl** to put security scores on every skill in the Tessl Registry — visible in UI and CLI at install time. First-party solution shipping now for Tessl users.

**Why it matters:** 36% isn't an edge case, it's the baseline. Every publicly-shared skill collection Leo might browse — including the awesome-claude-skills lists that have shown up in prior digests — should be treated as potentially containing compromised entries until verified. The Snyk+Tessl registry scores are the right infrastructure answer. Aguara (surfaced this AM) is the right offline scanner answer.
🔗 https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/

Build verdict: INFORMATIONAL — empirical research + registry partnership, not a skill to build.

### 4. Datadog Security Labs: Dynamic Context Bypasses Model Defenses Entirely
**Source:** securitylabs.datadoghq.com · **Score:** 7/10
The scariest finding in the security cluster: dynamic context commands (executable directives embedded in skills) run *before the model ever sees the skill*. Claude's prompt injection defenses get no chance to intervene. This means model-level safety reasoning is structurally bypassed for this class of attack — you need harness-level defenses (like Aguara's static scan, or SkillSieve's pre-run analysis) not just model judgment.
Build verdict: INFORMATIONAL — research finding, harness-level defense is the answer.
🔗 https://securitylabs.datadoghq.com/articles/malicious-skills-supply-chain-risks-in-coding-agents-with-dynamic-context/

### 7. arXiv:2605.11770 — 80% of 49,943 Skills Deviate from Declared Behavior (Palo Alto Networks)
**Source:** arxiv.org · **Score:** 7/10
Palo Alto Networks formalized the "Behavioral Integrity Verification (BIV)" problem: typed comparison between what a skill *claims* to do (in its description/metadata) and what it *actually* does (in its code/instructions). On 49,943 OpenClaw skills, 80.0% show at least one deviation. Four novel "compound-threat" categories identified. The method pairs deterministic code analysis with LLM-based capability extraction — this is the architecture underlying purpose-built skill scanners.
Build verdict: INFORMATIONAL — research paper, foundational for scanner design.
🔗 https://arxiv.org/abs/2605.11770

### 10. arXiv:2604.06550 — SkillSieve: 3-Layer Malicious Skill Detection (86% Benign in 40ms)
**Source:** arxiv.org · **Score:** 7/10
Academic paper on a practical detection architecture: Layer 1 (regex + AST + XGBoost metadata) filters 86% of benign skills in under 40ms at zero API cost. Layer 2 (4 parallel LLM subtasks: intent alignment, permission justification, covert behavior, cross-file consistency) catches ambiguous cases. Layer 3 (jury of 3 LLMs that debate disagreements) handles high-risk outliers. This is the closest thing to a "how to build a skill scanner yourself" recipe in the academic literature. Directly complements Aguara (static binary, no LLM) with an LLM-augmented approach.
Build verdict: INFORMATIONAL — paper, not a directly deployable skill yet. Note: if Leo wants a *native Jarvis skill scanner*, this is the architecture to build from. But Aguara should go first.
🔗 https://arxiv.org/abs/2604.06550
