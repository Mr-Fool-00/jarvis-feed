### 2. SkillJuror (arxiv:2606.11543): Progressive Disclosure makes agents use 3.3x more of their skills
**Source:** arxiv.org · **Score:** 7/10

Published June 10, 2026. SkillJuror is an 82-task controlled study measuring how skill *organization* (not just skill *content*) changes agent runtime behavior. The key comparison: **Flat baseline** (all skill content in one file) vs. **Progressive Disclosure** (concise root file with metadata pointers → full docs loaded on demand).

Results: Progressive Disclosure increases distinct skill resources touched per agent trajectory from 1.18 → 3.85. Effective uptake events: 1.33 → 3.92. Task completion: +4.1% (17 additional verifier-passing trials out of 410 matched). The finding isn't "use better skills" — it's "the same skills, organized differently, produce meaningfully different behavior."

The recommended structure: **Tier 1 (Activation)** — a root file with CLI syntax, endpoint signatures, common usage patterns (~50-100 tokens of metadata per skill). **Tier 2 (Reference)** — per-skill full docs loaded on demand. 133 skills organized this way use 7,000-13,000 tokens total for all metadata (vs. hundreds of thousands for flat). The agent self-selects which deep docs to pull when the task requires them.

**Why it matters:** Leo's current skill setup is almost certainly flat — each skill file contains all its content inline. This research says reorganizing into a root-file index (SKILL.md with metadata per skill + separate detailed docs) would measurably increase how many of Leo's skills actually get used per run. For a fiction pipeline with 10+ specialized skills, this is the difference between Claude ignoring the character-voice skill vs. proactively loading it when relevant. The improvement is +4.1% task completion but the behavioral change (3.3x more skill surface explored) is the real win.

**Build verdict:** BUILDABLE — restructure Leo's skill files using progressive disclosure. Root file = metadata index. Each skill gets its own `skills/<name>/README.md` with full docs. Leo approves the structure → Jarvis builds the reorganized version.
🔗 https://arxiv.org/abs/2606.11543
