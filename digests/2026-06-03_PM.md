## 🔥 Top 3

### 1. Dynamic Workflows vs /goal vs Agent Teams — The Decision Framework
**Source:** MindStudio blog · **Score:** 7/10
The most useful practitioner guide to emerge since Dynamic Workflows launched May 28. The core insight: **depth vs width**. `/goal` is depth-first — Claude drives one task to completion autonomously, keeps iterating until done, lowest cost. Dynamic Workflows is width-first — Claude spawns parallel subagents to simultaneously attack a problem from multiple angles, converges when answers agree, medium cost. Agent Teams is for genuinely independent parallel workers that each need full context isolation, highest cost and complexity. Cost ordering: /goal < Dynamic Workflows < Agent Teams.
**Why it matters:** Leo now has three orchestration tools and should pick deliberately per task type. Fiction pipeline mapping: **use /goal** for "polish this chapter with full continuity awareness" (one deep pass), **use Dynamic Workflows** for "check all 15 chapters for voice drift simultaneously" (width-first validation pass), **use Agent Teams** for "generate chapters 4, 5, and 6 in parallel" (independent parallel creation). This maps cleanly to the AM digest insight: single-agent beats multi-agent on quality per token, but parallel execution is valid for throughput when tasks are genuinely independent.
**Build verdict:** INFORMATIONAL — tutorial on built-in CC features, not a buildable skill. Direct change: apply this framework to fiction pipeline design.
🔗 https://www.mindstudio.ai/blog/dynamic-workflows-vs-goal-vs-agent-teams-claude-code

### 3. InfoQ: Dynamic Workflows Technical Analysis — What It Actually Does
**Source:** InfoQ news, June 2026 · **Score:** 5/10
InfoQ's practitioner analysis adds useful depth beyond the launch post: the agent-of-agents execution pattern (planning agent generates the workflow script, distributes tasks to worker agents, validates each result before folding it in), progress checkpointing (interrupted runs resume from saved state — no restart), and the 16 concurrent / 1,000 total subagent cap. Key finding from early adopters: biggest wins come from **investigation tasks** (security audits, performance analysis, cross-codebase consistency checks) where the answer path isn't known in advance. Sequential tasks where you already know the steps don't benefit from Dynamic Workflows — use /goal instead.
**Why it matters:** For Leo's fiction pipeline: Dynamic Workflows is the right tool for "find all continuity errors across the novel" or "identify all places where the protagonist's voice drifts" — investigation passes where parallel agents need to search independently and converge. NOT the right tool for sequential chapter writing where order matters.
**Build verdict:** INFORMATIONAL — practitioner analysis of built-in feature

### 5. Addy Osmani: Agentic Engine Optimization (AEO) — Late Discovery
**Source:** addyosmani.com (published April 11, 2026 — not caught in prior runs) · **Score:** 5/10
AEO = structuring your content and documentation so AI coding agents can actually consume it — not just human readers. The five dimensions: discoverability (robots.txt for AI bots, llms.txt presence), parsability (machine-readable without JavaScript), token efficiency (content fits in agent context without truncation), capability signaling (agent-permissions.json), and access control. Osmani shipped an open-source audit tool, `addyosmani/agentic-seo`, that checks a site against all AEO dimensions automatically. GitHub: `github.com/addyosmani/agentic-seo`.
**Why it matters:** Directly relevant to how Leo writes his SKILL.md files and fiction pipeline documentation. Poorly structured skill docs cause agents to misuse or skip skills. The AEO principles — especially token efficiency and parsability — are the same as good SKILL.md hygiene. Worth applying to any skill Leo writes this summer.
