### 1. GitHub Agentic Workflows — public preview (June 11)
**Source:** github.blog/changelog, dev.to/kochan, github.github.com/gh-aw · **Score:** 7/10

GitHub shipped its own scheduled/event-triggered agent automation layer on June 11. Write workflows as Markdown files, GitHub compiles them to Actions YAML. The agent engine is configurable: Claude Code, GitHub Copilot CLI, or OpenAI Codex. Sandboxed containers, Agent Workflow Firewall, read-only permissions by default. Runs on your existing GitHub Actions runner groups. Supported triggers: push, pull_request, schedule (cron), issue events — same event model as standard Actions.

Key differentiator from CCR: GitHub Agentic Workflows run inside GitHub's infrastructure using your own runner groups. CCR (this Jarvis routine) runs inside Anthropic's CCR cloud with its own network policy. The billing treatment is different — GitHub AW uses your existing GitHub Actions minutes quota (included in all GitHub plans), not Anthropic's Pool 2 credit.

**Why it matters:** This is directly relevant to two things: (1) The CCR billing ambiguity you have right now — if Jarvis ends up drawing Pool 2, GitHub AW is an architectural alternative for the scheduling layer. You'd still use Claude Code as the agent engine but the cron schedule would be managed by GitHub. (2) For your book pipeline, GitHub AW could trigger a chapter-review agent automatically on every push to your novel repo. The Markdown-native workflow definition means you could write the pipeline spec in plain language and let GitHub compile it to Actions.

### 2. Infini Memory: Topic-Document Architecture for Long-Term Agent Memory (arxiv:2606.10677)
**Source:** arxiv.org · **Score:** 7/10

Paper from June 9, 2026. Infini Memory proposes treating agent memory as topic-structured documents rather than flat logs or isolated records. Each "topic document" is a semantic unit: a named file that collects related observations, preserves metadata, and revises facts over time. New observations go into a staging buffer, get periodically consolidated into the relevant topic files. At inference time, the agent retrieves via iterative tool calls (multi-hop lookup) rather than a single embedding search.

Benchmark: 64.7% on MemoryAgentBench overall — significantly above flat RAG approaches. The iterative retrieval model (agent tool calls to navigate memory rather than one-shot search) is what drives the gain.

This is the same architecture your own agent_suggestions.md already pointed at (#100 from June 15 AM): "Infini Memory topic-document structure is the reference format for fiction pipeline memory." Now confirmed with benchmark numbers.

**Why it matters:** Your novel pipeline's memory problem is exactly this: by chapter 30, the writing agent has no reliable way to retrieve "what happened to Character X in chapter 12." A flat JSONL log requires searching through everything. Topic documents mean: `memory/characters/Elena.md`, `memory/plot/act-2-threads.md`, `memory/world/magic-system.md` — each one maintained and updated by the agent as it writes. Retrieval is "find the file" not "search everything." Briefing filed separately. This is the architectural target for your IS-CoT implementation.

🔗 https://arxiv.org/abs/2606.10677

Build verdict: BUILDABLE — implement topic-document memory/ structure in the fiction pipeline today. No new dependencies. Just file organization + a memory-update step in the chapter-write skill. Briefing at `briefings/2026-06-16_infini-memory-fiction-pipeline.md`. Pairs with IS-CoT (already briefed June 15).

### 3. CC v2.1.178 — Tool(param:value) permission syntax + subagent classifier pre-check
**Source:** releasebot.io, claudefa.st/changelog · **Score:** 5/10

Two useful additions in v2.1.178 (released June 15):

**Tool(param:value) permission syntax:** You can now scope permissions to specific argument values. Example: `allow: Bash(command:git*)` permits only bash commands starting with `git`, nothing else. Wildcards supported. Previously you had to choose between "allow all Bash" or "deny all Bash." This fills a real gap for tighter safety configurations without needing `--dangerously-skip-permissions`.

**Subagent spawn classifier pre-check:** Sub-agents are now evaluated by the safety classifier before they launch. Closes the gap where a nested sub-agent could request a blocked action without review. Relevant now that 5-level nesting is available — the previous model was that only the root session got classifier review.

Also: /doctor command improvements (flat tree layout, clearer status icons), file descriptor exhaustion fix in skill directories.

**Why it matters:** For your fiction pipeline, the Tool(param:value) syntax lets you create a settings.json that allows `Bash(command:git*)` and `Write(path:chapters/*)` while blocking everything else. You get full power for the allowed operations without `--dangerously-skip-permissions` being the only other option. Immediate config upgrade.

🔗 https://code.claude.com/docs/en/changelog
🔗 https://releasebot.io/updates/anthropic/claude-code

Build verdict: INFORMATIONAL — update CC to v2.1.178, add Tool(param:value) permission scoping to your pipeline settings.json.
