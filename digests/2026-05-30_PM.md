### 1. Ken Huang: "CLAUDE CODE ORCHESTRATION — Which Primitive For Which Problem"
**Source:** kenhuangus.substack.com · **Score:** 7/10  
Published May 28–29, this is the decision framework Leo actually needs *right now*. Ken breaks down when to use each of the three CC orchestration primitives — Dynamic Workflows (orchestration out-of-context-window, for huge tasks), Subagents (in-session parallel execution, for tasks that fan out within a single problem), and Agent Teams (persistent cooperating agents, for ongoing workflows). Key insight: the question is no longer "how do I prompt Claude for this?" — it's "what execution model fits the structure of this problem?" The guide includes a decision tree and cost/complexity tradeoffs per primitive.  
**Why it matters:** You're about to build `/book-pipeline` using the new primitives. This is the map. For fiction: use Dynamic Workflows for the full chapter fan-out (write 10 chapters in parallel with adversarial verification), use Subagents for per-scene consistency checks within a single chapter session, use Agent Teams for the persistent Writer+Editor+Reviewer structure that runs across a whole book. Don't conflate them — wrong primitive choice wastes tokens and produces incoherent handoffs.  
**Build verdict:** INFORMATIONAL — conceptual guide, not a skill to build. But it's the prereq for building `/book-pipeline` correctly.

The answer for your writing pipeline: use ultracode for the initial chapter-outline fan-out (worth the premium) and the final manuscript consistency sweep (worth it), not for every individual scene write (overkill, high effort is enough).
