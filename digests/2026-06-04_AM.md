### 3. Opus 4.8 Subagent Multiplication Bug — Anthropic Reset All Quotas June 1
**Source:** CybersecurityIntelligence, DevOps.com, The Register, GitHub issue #41084 · **Score:** 5/10

A bug in Opus 4.8 caused the model to spawn more parallel subagents than needed — each extra spawn burned tokens, rapidly draining Pro and Max 5-hour windows and weekly limits in minutes during ordinary tasks. Users hit zero allowance mid-session with no warning. Anthropic diagnosed the root cause as the way Opus 4.8 processes certain request patterns with high effort mode enabled, triggering redundant parallel tool calls. Emergency fix: Anthropic reset ALL 5-hour windows and weekly limits to zero for every Pro and Max user on June 1. The bug is being patched.

**Why it matters:** If your recent sessions have been hitting limits faster than expected, this is why. The reset means fresh limits as of June 1. Practical takeaway: if you're running large parallel fiction pipeline sessions (3 writers × 5 chapters), you may want to run them one pipeline at a time until Anthropic confirms the patch is live. The `waitingFor` field in v2.1.162 (item #2) helps diagnose if agents are piling up.

**Build verdict:** INFORMATIONAL — operational awareness, no skill needed.
