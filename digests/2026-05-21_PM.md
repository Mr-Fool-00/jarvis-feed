### 2. Addy Osmani: The Code Agent Orchestra — multi-agent orchestration patterns
**Source:** addyosmani.com/blog · **Score:** 8/10

Google Chrome engineering lead's comprehensive write-up on coordinating multiple AI coding agents. Three architecture tiers:

1. **Subagents** — focused delegation, parallel execution, no peer communication. Cheapest.
2. **Agent Teams** — shared task lists, peer-to-peer messaging, file locking. Best at 3-5 members.
3. **Hierarchical** — multi-level delegation mirroring real engineering orgs.

Key insights: **verification is now the bottleneck** (not generation), strong specs matter more than model choice, the **Ralph Loop** pattern (atomic task → implement → validate → commit → reset context → repeat) prevents context pollution, and **AGENTS.md** files compound institutional knowledge across sessions.

Three mandatory quality gates: plan approval before coding, automated hooks on lifecycle events, human-curated knowledge base (AGENTS.md).

**Why it matters:** Leo's fixer chain is already a Type 1 (subagent) orchestration. The Ralph Loop pattern is interesting for the writing pipeline — each chapter as an atomic unit, validate via verify-15, commit if clean, reset context. The AGENTS.md pattern maps to CLAUDE.md + collective fixer memory. The verification-as-bottleneck framing validates Leo's heavy investment in verify-15 and the fixer chain. The 3-5 member sweet spot for Agent Teams suggests Leo's 14-fixer chain is over-decomposed for parallel execution — might perform better as 3-4 bundled fixer groups.

**Build verdict:** INFORMATIONAL — excellent reference synthesis, but Leo's existing patterns already cover this ground. The Ralph Loop and fixer-bundling observations are worth noting but don't warrant a separate skill.

🔗 https://addyosmani.com/blog/code-agent-orchestra/

### 3. Book-Agent: Epistemic-controlled novel writing pipeline with revelation scheduling
**Source:** Level1Techs forum · **Score:** 8/10

A developer's 10-phase automated novel pipeline with a distinctive innovation: **epistemic tracking** — formally tracking what each character knows at each chapter, with a four-tier secrecy stratification:

- **Public** — known to all characters and readers
- **Hidden** — known to some characters, not readers (dramatic irony setup)
- **Delayed** — withheld from readers until a scheduled revelation chapter
- **Never-explicit** — implied but never stated (subtext layer)

Architecture: central `book_state.json` as single source of truth, clue generation with revelation scheduling, prose consistency layer using vector embeddings for repetition detection, "rotating opener templates" and "entropy injection" for stylistic variety. Currently runs on gpt-oss-20b locally (21-48 hours per book on a 2080Ti).

**Why it matters:** Leo's NO OMNISCIENCE rule is a hard constraint in CLAUDE.md — "characters only know what they have in-story reason to know." Currently this is enforced reactively by fixer-08 (brain-as-narrator, because-clause omniscience) AFTER prose is written. The epistemic tracker pattern would enforce it proactively BEFORE generation — maintaining a per-character knowledge ledger that the draft prompt consults. The revelation scheduling solves a related problem: when should readers learn X? Leo's current pipeline has no formal mechanism for this. The four-tier secrecy model is directly applicable to war-without-end's intelligence/espionage subplots.

**Build verdict:** INFORMATIONAL — fascinating architecture pattern. The epistemic tracking concept is genuinely novel for Leo's pipeline, but building it requires creative-mode decisions (Leo must define the knowledge taxonomy per story). Filing as inspiration for a future `knowledge-tracker` pipeline component.

🔗 https://forum.level1techs.com/t/my-ai-powered-novel-writing-pipeline-book-agent-generating-epistemically-controlled-long-form-fiction/243193
