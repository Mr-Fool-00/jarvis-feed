### 5. The Scaling Laws of Skills in LLM Agent Systems (arxiv:2605.16508)
**Source:** arxiv:2605.16508 · **Score:** 7/10
Empirical study across 15 frontier LLMs with 1,141 real-world skills, 3M+ routing decisions. Two coupled scaling laws discovered: (1) Routing accuracy decays **logarithmically** with library size — errors start with local skill competition, then cross-family drift, then "black-hole skills" that capture everything. (2) Correct execution can rescue ~4× improvement on difficult downstream decisions even when routing initially chose wrong. Single parameter (routing logarithmic decay slope) predicts execution-side rescue across all tested models.
Build verdict: INFORMATIONAL — architectural signal: Leo's skill library will hit routing degradation before it hits quality degradation; plan a skill selector/router tool when the library grows past ~50 skills
🔗 https://arxiv.org/abs/2605.16508

### 7. Claude Code Sandbox SOCKS5 Bypass — Silently Patched, No CVE Published
**Source:** security:cc-socks5-sandbox-bypass · **Score:** 6/10
Discovered: JavaScript's `endsWith()` check against the wildcard allowlist doesn't strip null bytes, so `attacker.com\x00.google.com` passes the `.google.com` check but resolves to `attacker.com` in the C runtime. Affected v2.0.24 through v2.1.89 (~130 releases, ~5.5 months). When paired with prompt injection, allows exfiltrating cloud credentials, GitHub tokens, and source code from the sandbox. Silently patched in v2.1.90 on April 1 — no CVE, no release-note mention. Second sandbox bypass disclosure in less than a year.
Build verdict: INFORMATIONAL — check `claude --version`; if v2.1.90+, already patched. If running on a credential-bearing system before April 1, rotate secrets. This is awareness, not a task.
🔗 https://oddguan.com/blog/second-time-same-sandbox-anthropic-claude-code-network-allowlist-bypass-data-exfiltration/
