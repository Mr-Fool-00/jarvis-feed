### 1. Novel Writing Structure for ClaudeCode: "writing environment design" not prompt engineering
**Score: 7/10** | Source: note.com/x2775co (Japanese, June 2026) | Build verdict: BUILDABLE

A Japanese developer published a complete template for novel writing with ClaudeCode, arguing the core problem is structural, not prompting. AI long-form writing fails because it lacks the structures human writers have implicitly — memory of settings, disciplined perspective, consistent timeline.

The fix: **FREEZE everything before you write a single word.**

Template structure:
- `world/settings.md` — geography, climate, social rules, faction structure. Locked before chapter 1.
- `characters/[name].md` — appearance, voice, backstory, contradictions, speech patterns. One file per character. NEVER rewrite in-session — append only.
- `timeline.md` — chronological event log updated after each chapter. Source of truth for "what already happened."
- `viewpoint.md` — whose POV, what they know vs. don't know. One line per chapter.
- `plot/arcs.md` — story beats with status: planned / in-progress / completed.

The key insight: Claude doesn't drift because of token limits — it drifts because it lacks the stable reference files human writers carry in their heads. The template makes those implicit structures explicit and frozen.

Why 7/10 for Leo: This is the pattern Leo's been circling in the context-drift problem for long-form writing. The "freeze-before-write" principle is directly applicable to the Jarvis writing pipeline. Build as a skeleton template repo or CC sub-agent skill. Also maps to Boris Cherny's Loop Engineering principle: environment > prompting.
