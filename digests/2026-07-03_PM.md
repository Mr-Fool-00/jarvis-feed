### 3. Simon Willison: DSPy for Agent Prompt Evaluation
**Source:** simonwillison.net · **Score:** 7/10
Simon used DSPy to run systematic prompt experiments against a live Datasette agent (rather than vibes-based iteration). He auto-generated a gold dataset from real user queries, then used DSPy's optimizer to find which system prompt variants scored highest. Key finding: a system prompt that listed only table names (not column names) combined with a "don't re-fetch schema" instruction caused the agent to hallucinate column names, then loop retrying when the queries failed. The fix: include columns in the schema context. More broadly: **match context granularity to action granularity** — if the agent needs to write SQL queries, it needs column-level context, not just table-level.

**Why it matters:** The schema-granularity insight applies directly to Leo's fiction pipeline. If a chapter-writing agent gets world-state context at the "locations exist" level but needs to write specific dialogue at a location, it will hallucinate details and retry. The fix is the same: include enough granularity in the context injection for the specific action the agent is taking. DSPy itself is also worth evaluating as a systematic prompt optimization tool for Jarvis's discovery loop prompts.
Build verdict: INFORMATIONAL — technique and insight, not a discrete skill to build today.
🔗 https://simonwillison.net/2026/Jul/2/dspy-datasette-agent-prompts/

### 4. AutoMem — Memory as Trainable Cognitive Skill (arxiv:2607.01224)
**Source:** arXiv · **Score:** 7/10
New paper frames agent memory not as a retrieval problem but as a trainable cognitive skill. Uses two meta-LLM optimization loops: one trains the memory-write strategy, one trains the memory-read strategy. Tested on LOCOMO and MemoryBench long-horizon tasks; achieves 2×–4× improvement over static RAG baselines. Key claim: current RAG memory underperforms because write and read strategies are designed independently; joint training dramatically improves retrieval relevance.
Build verdict: INFORMATIONAL — research result, no public implementation yet; track for when code drops.

### 5. Loom: Controllable Narrative Rendering via Intent-Centered Semiotic Chain-of-Thought (arxiv:2607.00009)
**Source:** arXiv · **Score:** 7/10
Loom addresses the "remedial polishing vs. destructive expansion" oscillation problem in writing agents — where revision agents repeatedly switch between over-trimming and over-adding content, never converging. The solution: add an "intent layer" to the chain-of-thought that explicitly encodes what the current scene is supposed to accomplish semiologically, so the revision agent knows which changes preserve intent vs. undermine it. Benchmarked on long-form fiction revision tasks; reduces oscillation cycles by ~60%.
Build verdict: INFORMATIONAL — directly relevant to Leo's writing pipeline revision agents, but paper-only for now.
🔗 https://arxiv.org/abs/2607.00009
